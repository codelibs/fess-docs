==================================
역할과 그룹으로 검색 결과 구분하기
==================================

들어가며
========

사내 문서를 하나의 Fess로 검색할 수 있게 되면, 다음으로 문제가 되는 것은 "누구에게 무엇을 보여 줄 것인가"입니다.
인사부의 평가 자료가 전 직원의 검색 결과에 나와서는 곤란하고, 반대로 전사 대상 규정이 일부 사람에게만 보이는 것도 곤란합니다.

Fess에서는 크롤링 설정의 "권한"에 적은 값이 문서마다 기록되고, 검색할 때마다 로그인한 사용자의 권한과 대조됩니다.
이 글에서는 부서별로 검색 결과를 구분하는 설정을 Fess 15.9에서 구성하고, 사용자별로 보이는 문서를 확인하는 데까지 차례대로 진행합니다.

이 글의 절차를 따라 하면 다음을 할 수 있게 됩니다.

- 부서·임원·전 직원의 3가지 공개 범위를 그룹과 권한으로 설정한다
- Active Directory의 그룹을 그대로 권한에 사용한다
- 라벨의 표시 범위를 문서와 같은 범위로 맞춘다
- 사용자별로 보이는 문서와 문서에 기록된 권한을 확인한다

SSO 설정은 :doc:`guide-15`\ 에서, 가상 호스트를 이용한 여러 조직의 구분은 :doc:`guide-13`\ 에서 다룹니다.

권한의 구조
===========

권한 작성 방법
--------------

크롤링 설정의 "권한"에는 다음 형식의 값을 한 줄에 하나씩 적습니다.
어느 하나라도 사용자의 권한과 일치하면 그 문서는 검색 결과에 표시됩니다.

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 작성 방법
     - 일치하는 사용자
   * - ``{user}사용자명``
     - 해당 사용자 본인
   * - ``{group}그룹명``
     - 해당 그룹에 소속된 사용자
   * - ``{role}역할명``
     - 해당 역할을 가진 사용자
   * - ``(deny){group}그룹명``
     - 일치한 사용자에게는 다른 값으로 허용되어 있어도 표시하지 않음(``{user}``\ 와 ``{role}``\ 에도 붙일 수 있습니다)

사용자가 가진 권한
------------------

검색할 때마다 Fess는 사용자의 권한을 다음과 같이 정합니다.

- 로그인한 사용자: 본인의 사용자명을 붙인 ``{user}``, 소속 그룹의 ``{group}``, 가진 역할의 ``{role}``
- 로그인하지 않은 방문자: ``{role}guest``

여기서 중요한 점은 로그인한 사용자에게는 ``{role}guest``\ 가 붙지 않는다는 것입니다.
새 크롤링 설정의 "권한"에는 ``{role}guest``\ 가 처음부터 들어 있습니다.
그대로 두면 로그인하지 않은 방문자에게는 보이고, 로그인한 사용자에게는 보이지 않는 문서가 됩니다.
전 직원에게 보여 주고 싶은 문서에는 전 직원이 소속된 그룹(또는 역할)을 권한에 적습니다.

또한 초기 사용자 ``admin``\ 은 역할 ``admin``\ 과 ``guest``\ 를 가지고 있습니다.
관리 화면에 로그인한 상태의 브라우저에서 검색하면 ``admin``\ 으로 검색되므로, ``{role}guest`` 문서만 표시되고 부서 문서는 표시되지 않습니다.

역할과 그룹의 구분
------------------

대조하는 방식은 역할과 그룹 모두 같습니다.
차이는 값의 출처입니다.
Fess의 사용자 관리에서는 사용자마다 역할과 그룹을 모두 할당할 수 있습니다.
LDAP(Active Directory) 연동에서는 소속 그룹(``memberOf``)이 ``{group}그룹명``\ 이 됩니다(DN에 ``ou=Role``\ 을 포함하는 항목만 ``{role}``\ 이 됩니다).

이 글에서는 Fess 사용자에서도 Active Directory에서도 같은 권한 값을 사용할 수 있도록, 부서나 전 직원 같은 조직 단위를 모두 그룹으로 나타냅니다.

   * - ``suzuki``

   * - ``tanaka``

     - ``HR``, ``AllStaff``
   * - ``yamada``

.. list-table:: 크롤링 설정의 권한
   :header-rows: 1

     - URL
     - 권한
   * - 영업부

     - ``{group}Sales``\ 와 ``{group}Executives``
   * - 개발부
     - ``https://intra.example.com/dev/``
     - ``{group}Engineering``\ 과 ``{group}Executives``
   * - 인사부
     - ``https://intra.example.com/hr/``

이 설정에서 사용자별로 보이는 문서는 다음과 같습니다.

.. list-table:: 사용자별로 보이는 문서
   :header-rows: 1
   :widths: 30 70

   * - 사용자
     - 검색 결과에 나오는 문서
   * - ``sato``
     - 영업부, 전사 공통
   * - ``suzuki``
     - 개발부, 전사 공통
   * - ``tanaka``
     - 인사부, 전사 공통
   * - ``yamada``
     - 영업부, 개발부, 인사부, 전사 공통
   * - 로그인하지 않은 방문자
     - 없음
   * - ``admin``\ (검색 화면)
     - 없음

로그인하지 않은 방문자에게도 전사 공통 문서를 보여 주고 싶다면, 전사 공통 설정에 ``{role}guest``\ 도 추가합니다.
이 경우 ``admin``\ 에게도 전사 공통 문서가 표시됩니다.

그룹명은 대소문자를 구분하여 대조됩니다.
``{group}sales``\ 와 ``{group}Sales``\ 는 서로 다른 그룹으로 취급되므로, 그룹 이름과 권한 값은 같은 철자로 적습니다.

Fess 사용자로 설정하기
======================

그룹과 사용자 만들기
--------------------

1. 관리 화면의 [사용자] > [그룹]에서 [새로 만들기]를 클릭하고, "이름"에 ``Sales``\ 를 입력한 뒤 [작성]을 클릭합니다. ``Engineering``, ``HR``, ``Executives``, ``AllStaff``\ 도 같은 방법으로 작성합니다
2. [사용자] > [사용자]에서 [새로 만들기]를 클릭하고 "사용자명", "비밀번호", "비밀번호(확인)"를 입력합니다. 비밀번호는 8자 이상으로 합니다
3. "그룹"에서 위 표대로 소속 그룹을 선택하고 [작성]을 클릭합니다

사용자, 그룹, 역할은 OpenSearch에 저장되므로 Docker에서 컨테이너를 다시 만들어도 남습니다.

크롤링 설정 만들기
------------------

부서별로 [크롤러] > [웹]에서 크롤링 설정을 만듭니다.
다음 표는 영업부의 예입니다.

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 항목
     - 값
   * - 이름
     - ``영업부 포털``
   * - URL
     - ``https://intra.example.com/sales/``
   * - 크롤링할 URL
     - ``https://intra.example.com/sales/.*``
   * - 권한
     - 초깃값 ``{role}guest``\ 를 지우고 다음 2줄을 입력합니다

::

    {group}Sales
    {group}Executives

개발부·인사부·전사 공통도 URL과 권한을 표대로 바꾸어 작성합니다.
작성한 뒤 [시스템] > [스케줄러]의 "Default Crawler"에서 [지금 시작]을 클릭하여 크롤링을 실행합니다.
크롤링 완료를 확인하는 방법은 :doc:`guide-02`\ 를 참조하세요.

.. note::

   파일 시스템 크롤링 설정(SMB나 로컬 파일)에서는 파일의 ACL에서 읽어 들인 권한이 "권한"의 값에 **더하여** 문서에 기록됩니다.
   이 동작은 기본적으로 활성화되어 있습니다.
   따라서 파일 서버의 문서는 "권한"에 적은 범위보다 넓게 표시될 수 있습니다.
   ACL과의 조합 방법은 :doc:`file-server-search`\ 를 참조하세요.
   데이터 스토어 크롤링 설정의 권한은 :doc:`datastore-basics`\ 에서 다룹니다.

Active Directory의 그룹 사용하기
================================

사용자를 Active Directory로 관리하고 있다면, Fess에 사용자나 그룹을 만드는 대신 LDAP 연동을 설정합니다.
로그인한 사용자의 ``memberOf`` 속성에 들어 있는 그룹이 ``{group}`` 권한이 됩니다.

LDAP 연결 설정하기
------------------

[시스템] > [일반]의 "LDAP" 섹션에 입력하고 [갱신]을 클릭합니다.

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 항목
     - 입력 예
   * - LDAP URL
     - ``ldap://ad.example.com:389``
   * - 베이스 DN
     - ``dc=example,dc=com``
   * - 바인드 DN
     - ``cn=fess,cn=Users,dc=example,dc=com``\ (검색용 서비스 계정)
   * - 비밀번호
     - 서비스 계정의 비밀번호
   * - 사용자 DN
     - ``%s@example.com``\ (``%s``\ 에 로그인 이름이 들어갑니다)
   * - 계정 필터
     - ``sAMAccountName=%s``
   * - memberOf 속성
     - ``memberOf``

각 항목의 자세한 내용과 중첩된 그룹을 해석하기 위한 "그룹 필터" 작성 방법은 `LDAP 통합 가이드 <https://fess.codelibs.org/ko/stable/config/ldap-integration.html>`__\ 를 참조하세요.

.. warning::

   [일반] 설정은 ``system.properties``\ 에 저장됩니다.
   docker-fess 구성에서는 이 파일이 ``fess01`` 컨테이너 안에 있으므로, ``down`` → ``up``\ 으로 컨테이너를 다시 만들면 사라집니다(:doc:`guide-02`\ 의 중지와 재개에 관한 절 참조).

그룹명과 권한의 대응
--------------------

그룹 DN 중 가장 말단의 ``CN`` 값이 그룹명이 됩니다.

.. list-table::
   :header-rows: 1
   :widths: 55 45

   * - memberOf 값
     - 사용자의 권한
   * - ``CN=Sales,OU=Groups,DC=example,DC=com``
     - ``{group}Sales``
   * - ``CN=AllStaff,OU=Groups,DC=example,DC=com``
     - ``{group}AllStaff``

Active Directory 쪽 그룹명을 ``Sales``·``Engineering``·``HR``·``Executives``·``AllStaff``\ 로 해 두면, 앞 장의 크롤링 설정을 그대로 사용할 수 있습니다.
이름이 다른 경우에는 권한 값을 Active Directory의 그룹명에 맞추어 고쳐 씁니다.

전 직원용 그룹으로는 모든 사람이 직접 소속된 그룹을 준비하세요.
Active Directory의 기본 그룹(보통 ``Domain Users``)은 ``memberOf`` 속성에 포함되지 않으므로, ``{group}Domain Users``\ 라고 적어도 일치하지 않습니다.

사용자에게 어떤 권한이 붙었는지는 ``org.codelibs.fess.ldap`` 로그를 DEBUG로 하면 확인할 수 있습니다.
LDAP에서 권한을 가져올 때 ``Roles:``\ 로 시작하는 줄이 ``fess.log``\ 에 출력됩니다.
설정 방법은 LDAP 통합 가이드의 "디버그 설정"을 참조하세요.
이 줄의 값은 뒤에서 설명하는 내부 형식(``2Sales`` 등)으로 표시됩니다.

SSO(Entra ID, OpenID Connect, SAML, SPNEGO)로 로그인하게 하려면 방식별로 ``fess-sso-*`` 플러그인이 필요합니다.
그룹이나 역할을 받는 방법도 방식마다 다르므로 :doc:`guide-15`\ 를 참조하세요.

라벨의 표시 범위 맞추기
=======================

라벨에도 "권한"이 있으며, 검색 화면의 라벨 선택지에 그 라벨을 표시할지를 결정합니다.
문서를 보여 줄지에는 영향을 주지 않지만, 새 라벨에도 ``{role}guest``\ 가 처음부터 들어 있으므로 그대로 두면 로그인한 사용자의 선택지에 표시되지 않습니다.

인사부 문서에 붙일 라벨의 예입니다.
[크롤러] > [라벨]에서 [새로 만들기]를 클릭하고 다음과 같이 입력합니다.

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 항목
     - 값
   * - 이름
     - ``인사부``
   * - 값
     - ``hr``\ (영숫자와 밑줄만)
   * - 대상 경로
     - ``https://intra.example.com/hr/.*``
   * - 권한
     - ``{group}HR``\ 과 ``{group}Executives``\ (문서와 같은 범위)

라벨의 권한은 저장한 시점에 선택지에 반영됩니다.
반면 라벨을 문서에 붙이는 "대상 경로"는 크롤링할 때 적용되므로, 라벨을 만든 뒤 크롤링을 실행합니다.

권한을 바꾸면 다시 크롤링하기
=============================

권한은 크롤링할 때 문서에 기록됩니다.
크롤링 설정의 "권한"을 변경해도 이미 인덱스에 있는 문서의 권한은 바뀌지 않습니다.
변경한 뒤 그 크롤링 설정을 포함하는 작업("Default Crawler" 등)을 실행하세요.

웹과 파일 시스템 크롤링 설정에서는 권한이 바뀐 문서를 다음 크롤링에서 다시 가져오고, 같은 URL의 오래된 문서는 교체됩니다.
다시 크롤링이 끝날 때까지는 이전 권한 그대로 검색 결과에 계속 나옵니다.
공개 범위를 좁혔을 때는 바로 크롤링을 실행하세요.

특정 크롤링 설정만 바로 다시 크롤링하고 싶다면, 그 크롤링 설정의 상세 화면에서 [새 작업 작성]을 클릭하고, 만든 작업을 [지금 시작]으로 실행합니다.

동작 확인하기
=============

사용자별로 검색하기
-------------------

1. 브라우저의 시크릿 창에서 ``http://localhost:8080/``\ 을 엽니다. 관리 화면에 로그인한 창에서는 ``admin``\ 으로 검색되기 때문입니다
2. 로그인하지 않고 검색하여 부서와 전사 공통 문서가 표시되지 않는 것을 확인합니다
3. 검색 화면 상단의 로그인 링크에서 ``sato``\ 로 로그인하여 영업부와 전사 공통 문서만 표시되는 것을 확인합니다
4. 화면 상단의 사용자명을 클릭하여 "로그아웃"을 선택하고, ``suzuki``, ``tanaka``, ``yamada``\ 로도 같은 방법으로 확인합니다

확인할 때는 모든 문서에 포함된 단어(예: 회사명)로 검색하면 표시되는 문서의 범위를 비교하기 쉬워집니다.

문서에 기록된 권한 보기
-----------------------

생각한 대로 표시되지 않는 경우에는 문서에 기록된 권한을 확인합니다.

1. 관리 화면의 [시스템 정보] > [검색]을 열고, 문서의 URL이나 제목에 있는 단어로 검색합니다. 이 화면은 권한으로 걸러 내지 않고 모든 문서를 표시합니다
2. 대상 문서의 [갱신]을 클릭하면 편집 화면이 열리고, ``role`` 필드에 기록된 권한이 표시됩니다. 확인만 하고 저장하지는 마세요

``role`` 필드의 값은 다음 내부 형식으로 표시됩니다.

.. list-table::
   :header-rows: 1
   :widths: 35 30 35

   * - 권한
     - role 필드의 표시
     - 예
   * - ``{user}사용자명``
     - ``1`` + 이름
     - ``1sato``
   * - ``{group}그룹명``
     - ``2`` + 이름
     - ``2Sales``
   * - ``{role}역할명``
     - ``R`` + 이름
     - ``Rguest``
   * - ``(deny)`` 포함
     - 앞에 ``D``
     - ``D2Sales``

영업부 문서의 ``role`` 필드가 ``2Sales``\ 와 ``2Executives``\ 라면 권한은 설정대로 기록되어 있습니다.
``Rguest``\ 가 남아 있다면 권한을 변경한 뒤 다시 크롤링하지 않았거나, 초깃값 ``{role}guest``\ 를 지우는 것을 잊은 것입니다.

로그인하지 않은 사용자에게 아무것도 보여 주지 않기
==================================================

외부 사람이 접근할 수 있는 네트워크에 Fess를 두는 경우나, 애초에 로그인하지 않은 검색을 허용하지 않는 경우에는 [시스템] > [일반]의 "로그인 필요"를 활성화합니다.
활성화하면 로그인하지 않은 방문자는 검색할 수 없게 됩니다.

권한에 의한 구분과는 독립적인 설정입니다.
``{role}guest``\ 가 붙은 문서가 남아 있더라도 로그인하지 않은 방문자에게 표시되는 일은 없어집니다.
이 설정도 ``system.properties``\ 에 저장되므로, Docker에서는 LDAP 설정과 같은 주의가 필요합니다.
