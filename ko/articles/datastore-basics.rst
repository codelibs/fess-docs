=========================
데이터 저장소 크롤링 기본
=========================

들어가며
========

Google Drive나 Slack, 데이터베이스의 내용은 웹 크롤링이나 파일 크롤링으로는 검색 대상으로 만들 수 없습니다.
CSV 파일도 파일 크롤링으로는 파일 1개가 문서 1건이 되므로, 행 단위로 검색할 수 없습니다.
Fess에서는 이러한 소스를 "데이터 저장소"로 다루며, 플러그인(데이터 저장소 커넥터)을 통해 레코드 단위로 가져옵니다.

데이터 저장소 설정 화면은 웹이나 파일 시스템 설정 화면과 항목이 다릅니다.
어떤 값을 URL이나 제목으로 할지 직접 작성해야 하며, 초깃값 그대로 두면 로그인 없이 검색할 수 있는 상태로 등록됩니다.
처리에 실패해도 작업이 "OK"로 표시되는 경우가 있습니다.

이 글에서는 모든 커넥터에 공통되는 구조를 Fess 15.9를 기준으로 설명합니다.
CSV 파일을 사용한 작은 예제로 플러그인 설치부터 설정, 실행, 결과 확인까지 한 번에 진행합니다.
커넥터별 인증이나 파라미터는 끝에 나열한 각 글과 레퍼런스를 참조하십시오.

웹·파일 크롤링과의 차이
=======================

웹 크롤링과 파일 크롤링에서는 Fess가 링크나 폴더를 따라가며, 가져온 문서에서 제목과 본문을 자동으로 추출합니다.
데이터 저장소 크롤링에서는 커넥터가 API나 파일에서 레코드를 읽어 옵니다.
그 레코드의 어떤 값을 인덱스의 어떤 필드에 넣을지는 설정의 "스크립트"에 작성합니다.

Fess 본체에는 데이터 저장소 핸들러가 포함되어 있지 않습니다.
[크롤러] > [데이터 저장소]의 "핸들러 이름" 드롭다운에 표시되는 것은 설치된 ``fess-ds-*`` 플러그인이 제공하는 핸들러뿐입니다.

이 밖에도 데이터 저장소 설정에는 다음과 같은 차이가 있습니다(뒤의 절에서 설명합니다).

- 설정 화면에 "라벨" 항목이 없음
- [크롤러] > [문서 부스트]의 규칙이 적용되지 않음

플러그인 설치하기
=================

여기서는 예로 CSV 커넥터 ``fess-ds-csv``\ 를 사용합니다.
플러그인 버전은 사용 중인 Fess의 마이너 버전에 맞춥니다(15.9라면 15.9.x).

관리 화면에서 설치하는 경우에는 [시스템] > [플러그인]에서 [설치]를 클릭합니다.
[원격] 탭의 드롭다운에서 ``fess-ds-csv``\ 를 선택하고 [설치]를 클릭합니다.
가지고 있는 jar 파일을 사용하는 경우에는 [로컬] 탭을 사용합니다.

ZIP 패키지나 RPM / DEB로 설치한 환경에서는 명령줄에서도 설치할 수 있습니다.

.. code-block:: bash

    bin/fess-setup install plugin fess-ds-csv:15.9.0

Docker에서는 ``compose.yaml``\ 의 ``fess01``\ 의 ``environment``\ 에 ``FESS_PLUGINS``\ 를 추가하여 시작할 때 설치합니다.
여러 플러그인은 공백으로 구분하여 나열합니다(쉼표 구분이 아닙니다).

.. code-block:: yaml

    environment:
      - "FESS_PLUGINS=fess-ds-csv:15.9.0"

.. code-block:: bash

    docker compose -f compose.yaml -f compose-opensearch3.yaml up -d

Docker에서 관리 화면으로 설치한 플러그인은 컨테이너 안에 놓이므로, 컨테이너를 다시 만들면 사라집니다.
Docker에서는 ``FESS_PLUGINS``\ 를 사용하는 편이 확실합니다.
환경 변수를 바꾸고 ``up -d``\ 를 실행하면 컨테이너가 다시 만들어집니다.
그때 사라지는 설정에 대해서는 :doc:`guide-02`\ 를 참조하십시오.

관리 화면이나 ``fess-setup``\ 으로 설치한 경우에는 Fess를 재시작합니다(``FESS_PLUGINS``\ 는 Fess가 시작되기 전에 설치하므로 재시작이 필요 없습니다).
재시작 후 [크롤러] > [데이터 저장소] > [새로 만들기]의 "핸들러 이름"에 ``CsvDataStore``\ 가 표시되면 설치된 것입니다.

설정 화면의 3가지 항목
======================

데이터 저장소 설정의 중심은 "핸들러 이름", "파라미터", "스크립트"의 3가지 항목입니다.

.. list-table::
   :header-rows: 1
   :widths: 20 80

   * - 항목
     - 내용
   * - 핸들러 이름
     - 사용할 커넥터. 예: ``CsvDataStore``, ``SlackDataStore``
   * - 파라미터
     - 커넥터에 대한 지시. 한 줄에 하나씩 ``키=값``\ 으로 작성(읽을 파일, 접속 대상, 인증 정보 등)
   * - 스크립트
     - 인덱스 필드와의 대응. 한 줄에 하나씩 ``필드명=식``\ 으로 작성

파라미터의 ``script_type``
--------------------------

새로 만들기 화면의 "파라미터" 항목에는 처음부터 ``script_type=javascript``\ 가 들어 있습니다.
이는 "스크립트" 항목의 식을 JavaScript로 평가한다는 지정입니다.
커넥터의 파라미터는 이 줄을 남겨 둔 채 아래에 추가합니다.

``script_type`` 줄을 지우면 스크립트는 Groovy로 평가됩니다(15.9 이전에 만든 설정이 계속 동작하도록 하기 위한 기본값입니다).
Groovy로 평가하려면 ``fess-script-groovy`` 플러그인이 필요합니다.
표준 Docker 이미지에는 포함되어 있지만 slim 이미지에는 포함되어 있지 않습니다.
플러그인이 없는 환경에서는 식을 포함한 줄의 평가가 ``groovy is not found`` 오류로 실패하고, 그 레코드는 등록되지 않습니다(``title=subject``\ 처럼 우변이 항목 이름뿐인 줄은 스크립트 엔진을 거치지 않고 값이 그대로 사용됩니다).
반대로 표준 Docker 이미지에서는 줄을 지워도 Groovy로 평가되어 동작하므로 알아차리기 어렵습니다.
커넥터 레퍼런스에 있는 예를 "파라미터" 항목에 붙여 넣을 때는 ``script_type=javascript`` 줄을 지우지 않도록 하십시오.

스크립트 작성법
---------------

"스크립트" 항목의 각 줄은 좌변이 인덱스의 필드 이름, 우변이 JavaScript 식입니다.
문자열은 큰따옴표로 감쌉니다.
줄 끝에 세미콜론을 붙이지 마십시오.
세미콜론을 붙이면 식의 값이 ``null``\ 이 되어 그 필드에는 아무것도 설정되지 않습니다.
오류나 로그가 출력되지 않으므로 필드가 비어 있는 것으로만 알아차릴 수 있습니다(자세한 내용은 끝에 있는 레퍼런스의 "JavaScript 스크립트 가이드"를 참조).

우변에서 참조할 수 있는 항목 이름은 커넥터에 따라 다릅니다.

- CSV·JSON·데이터베이스 커넥터는 열 이름이나 필드 이름을 그대로 참조합니다(CSV는 ``cell1``, ``cell2`` … 로도 참조할 수 있습니다)
- 많은 클라우드 계열 커넥터는 가져온 객체를 접두사를 붙여 전달합니다. 예를 들어 Box·Google Drive·OneDrive는 ``file.*``, Slack은 ``message.*``, Jira는 ``issue.*``, Salesforce는 ``object.*``\ 입니다

사용할 수 있는 항목 이름은 각 커넥터 레퍼런스(``https://fess.codelibs.org/ko/stable/config/datastore/ds-<이름>.html``)의 스크립트 설명에서 확인하십시오.
``file.url``\ 이라고 해야 할 곳에 ``url``\ 이라고 쓰는 등 정의되지 않은 이름을 참조하면 식의 평가가 실패하고, 그 레코드는 등록되지 않습니다.

예: CSV 파일을 검색할 수 있게 하기
==================================

사내 FAQ를 CSV로 관리하고 있고, 이를 검색할 수 있게 하는 예입니다.
다음 내용을 UTF-8로 ``faq.csv``\ 라는 이름으로 저장합니다.

.. code-block:: text

    faq_id,question,answer
    1,경비 정산 마감일은 언제입니까,경비는 매월 말까지 신청하십시오.
    2,사외에서 사내 시스템에 접속하려면,VPN 클라이언트를 사용하여 접속하십시오.
    3,출입증을 분실했을 때는,총무부에 연락하여 재발급을 요청하십시오.

Excel로 저장한 CSV는 UTF-8이 아니라 Windows의 기존 인코딩인 경우가 많습니다(한국어 Excel이라면 MS949, 일본어 Excel이라면 MS932).
그런 경우에는 뒤에 나오는 파라미터에 ``file_encoding=MS949`` 또는 ``file_encoding=MS932``\ 처럼 인코딩을 지정합니다.
파일은 Fess 크롤러가 읽을 수 있는 경로에 둡니다.
크롤러는 Fess와 같은 서버에서 동작하므로, ZIP이나 RPM / DEB 환경에서는 Fess를 실행하는 사용자가 읽을 수 있는 디렉터리에 둡니다.
Docker에서 시험만 해 보는 경우에는 컨테이너 안에 복사하는 방법이 간편합니다(컨테이너를 다시 만들면 사라집니다).

.. code-block:: bash

    docker cp faq.csv fess01:/tmp/faq.csv

[크롤러] > [데이터 저장소]에서 [새로 만들기]를 클릭하고 다음과 같이 입력합니다.

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - 항목
     - 값
   * - 이름
     - 사내 FAQ
   * - 핸들러 이름
     - ``CsvDataStore``
   * - 파라미터
     - 아래 참조
   * - 스크립트
     - 아래 참조
   * - 권한
     - ``{role}guest`` 그대로(로그인 없이 검색해도 되는 FAQ이므로)

파라미터:

.. code-block:: properties

    script_type=javascript
    files=/tmp/faq.csv
    file_encoding=UTF-8
    has_header_line=true

스크립트:

.. code-block:: javascript

    url="https://intranet.example.com/faq/" + faq_id
    title=question
    content=question + " " + answer
    digest=answer
    label="faq"

``has_header_line=true``\ 를 지정하면 첫 번째 줄의 열 이름(``faq_id``, ``question``, ``answer``)을 스크립트에서 참조할 수 있습니다.
``url``\ 에는 검색 결과의 링크를 클릭했을 때 열리는, 그 레코드를 표시할 수 있는 페이지의 URL을 지정합니다.
이 예의 URL은 가상의 것입니다.
실제 FAQ 페이지의 URL로 바꾸십시오.

[작성]으로 저장했으면, 뒤에서 설명하는 "스케줄" 절차로 작업을 만들어 실행하고, "결과 확인하기" 절차로 확인합니다.
잘 되었다면 로그아웃한 상태(또는 브라우저의 시크릿 창)의 검색 화면에서 "VPN"으로 검색하면 두 번째 FAQ가 검색됩니다.
``{role}guest`` 문서는 로그인하지 않은 이용자와 ``guest`` 롤을 가진 사용자(초기 사용자 ``admin`` 포함)에게 표시됩니다. 다른 사용자로 로그인한 경우에는 표시되지 않습니다.

라벨 ``faq``\ 를 검색 화면의 필터에 표시하려면 [크롤러] > [라벨]에서 "값"이 ``faq``\ 인 라벨을 만듭니다(다음 "라벨" 절 참조).

인덱스 필드
===========

스크립트에서 자주 설정하는 필드는 다음과 같습니다.

.. list-table::
   :header-rows: 1
   :widths: 20 80

   * - 필드
     - 설명
   * - ``url``
     - 필수. 검색 결과의 링크 대상. 레코드마다 고유한 값으로 함
   * - ``title``
     - 검색 결과의 제목. 검색 대상
   * - ``content``
     - 본문. 검색 대상
   * - ``digest``
     - 검색 결과에 표시하는 요약
   * - ``label``
     - 라벨 값(후술)
   * - ``role``
     - 열람할 수 있는 롤. 커넥터가 ACL을 제공하는 경우에 사용(후술)

이 밖에 ``config_id``, ``boost``, ``role``, ``virtual_host``, ``mimetype`` 등은 자동으로 설정됩니다(``boost``, ``role``, ``virtual_host``\ 는 설정 화면의 "부스트 값", "권한", "가상 호스트"의 값입니다).
스크립트에서 같은 필드를 지정한 경우에는 스크립트의 값으로 덮어씁니다.

``url``\ 은 다음 사항에 주의하십시오.

- 식의 값이 ``null``\ 이 된 레코드는 등록되지 않습니다. CSV 커넥터는 그러한 행을 장애 URL에 기록하지 않고, ``fess-crawler.log``\ 에 건수를 WARN으로 1줄 출력할 뿐입니다
- 문서 ID는 URL, 롤, 가상 호스트로 만들어집니다. ``url``\ 이 빈 문자열인 레코드나 ``url``\ 이 같은 레코드는 롤과 가상 호스트도 같다면 같은 문서 ID가 되어 서로 덮어쓰며, 마지막 1건만 남습니다

권한
====

새로 만들기 화면의 "권한"에는 처음부터 ``{role}guest``\ 가 들어 있습니다.
이 값은 그 데이터 저장소에서 등록되는 모든 문서의 롤이 됩니다.
게스트 롤은 로그인하지 않은 이용자에게 부여되므로, 이대로라면 문서는 로그인 없이 검색할 수 있습니다.
사내 FAQ처럼 공개해도 되는 데이터라면 이대로 두어도 됩니다.

열람자를 한정하고 싶은 데이터는 다음 중 하나로 제어합니다.

- "권한" 항목을 보여 주고 싶은 그룹이나 롤(예: ``{group}sales``)로 바꿉니다. 데이터 저장소 안의 모든 문서에 같은 권한이 붙습니다
- 커넥터가 원본 서비스의 공유 설정(ACL)으로 롤을 만드는 경우에는 스크립트에서 ``role=file.roles``\ 처럼 대응시킵니다. 항목 이름은 커넥터에 따라 다르며(Slack은 ``message.roles``), ACL을 가져오는 데 추가 파라미터가 필요한 커넥터도 있습니다(Slack의 ``permission_sync=true`` 등). 각 커넥터의 레퍼런스를 확인하십시오

ACL을 사용하는 경우에는 "권한" 항목의 ``{role}guest``\ 를 지우십시오.
Box, Slack, Microsoft 365(OneDrive) 등의 커넥터는 "권한" 항목의 값도 ``file.roles`` / ``message.roles``\ 에 더해서 반환합니다.
따라서 ``{role}guest``\ 를 남겨 두면 ACL을 설정해도 로그인 없이 검색할 수 있는 상태 그대로입니다.

반대로 "권한" 항목을 비우고 스크립트에서도 ``role``\ 을 설정하지 않으면 문서에 롤이 하나도 붙지 않습니다.
이 문서는 검색 화면에서 누구에게도 표시되지 않습니다.

롤은 문서를 등록할 때 기록됩니다.
권한이나 스크립트를 변경한 경우에는 다시 크롤링할 때까지 기존 문서에 반영되지 않습니다.
롤과 그룹의 설계는 :doc:`guide-05`\ 에서 설명합니다.

라벨
====

데이터 저장소 설정 화면에는 웹이나 파일 시스템 설정 화면에 있는 "라벨" 항목이 없습니다.
라벨을 붙이려면 다음 중 하나를 사용합니다.

- 스크립트에 ``label="faq"``\ 처럼 작성합니다. 그 데이터 저장소의 모든 문서에 붙습니다
- [크롤러] > [라벨]에서 "대상 경로"에 문서의 URL과 일치하는 정규 표현식을 작성합니다. 등록할 때 URL이 이 정규 표현식과 대조되어, 일치한 문서에 라벨이 붙습니다

"대상 경로"는 URL 전체와의 일치로 판정되므로, 전방 일치로 하려면 끝에 ``.*``\ 를 붙입니다(예: ``https://intranet\.example\.com/faq/.*``).

주의: 스크립트로 붙인 라벨은 그 문서의 URL과 일치하는 라벨이 [크롤러] > [라벨]에 하나라도 있으면 사라지고, 일치한 라벨만 남습니다.
웹 크롤링용으로 만든 라벨(예: ``https://intranet\.example\.com/.*``)이나 "제외 경로"만 설정한 라벨도 일치 대상입니다.
스크립트로 라벨을 붙이는 경우에는 문서의 URL과 일치하는 라벨이 없는지 확인하십시오.

라벨의 "값"은 영숫자와 밑줄만으로 지정합니다(하이픈이나 한글 같은 비ASCII 문자는 사용할 수 없습니다).
검색 화면의 라벨 선택지에 표시하려면, 스크립트로 붙이는 경우에도 같은 값의 라벨을 [크롤러] > [라벨]에 등록하십시오.
그 경우 "대상 경로"는 비워 두어도 됩니다.

부스트 값
=========

데이터 저장소 설정 화면의 "부스트 값"(초깃값 ``1.0``)은 그 데이터 저장소에서 등록되는 모든 문서에 설정됩니다.
부스트 값은 검색할 때 점수에 곱해집니다.
특정 데이터 소스의 문서를 상위에 표시하고 싶은 경우에는 이 부스트 값을 바꿉니다.

[크롤러] > [문서 부스트]의 규칙은 웹 크롤링과 파일 크롤링으로 등록하는 문서에만 적용됩니다.
데이터 저장소의 문서에는 적용되지 않습니다.

스케줄
======

초기 상태의 작업 "Default Crawler"는 매일 0:00에 실행되며, 활성화된 웹·파일 시스템·데이터 저장소 설정을 모두 크롤링합니다.
데이터 저장소마다 실행 빈도를 바꾸고 싶은 경우에는 설정마다 작업을 만듭니다.

1. [크롤러] > [데이터 저장소] 목록에서 설정 이름을 클릭하여 상세 화면을 엽니다
2. [새 작업 작성]을 클릭합니다. 스케줄러 작성 화면이 열리고, "이름"(``Data Crawler - 사내 FAQ``)과 이 설정만 크롤링하는 스크립트가 입력되어 있습니다
3. "스케줄"에 cron 형식(분 시 일 월 요일)으로 실행 시각을 입력하고 [작성]을 클릭합니다. 예: ``0 2 * * *``\ (매일 2:00)

"스케줄"이 비어 있는 작업은 정기적으로 실행되지 않으며, 수동으로만 실행됩니다.
바로 시험해 보려면 [시스템] > [스케줄러]에서 만든 작업을 열고 [지금 시작]을 클릭합니다.

설정마다 작업을 만들어도 "Default Crawler"는 계속해서 그 설정도 크롤링합니다.
중복 실행을 원하지 않는 경우에는 그 데이터 저장소 설정의 "상태"를 비활성화합니다.
"Default Crawler"는 활성화된 설정만 대상으로 하지만, 설정 ID를 지정한 작업은 비활성화된 설정도 크롤링합니다.
모든 설정에 전용 작업을 만드는 경우에는 "Default Crawler"의 "스케줄"을 비우는 방법도 있습니다(:doc:`guide-04` 참조).

문서의 유효 기간
================

데이터 저장소로 등록한 문서에는 유효 기간이 붙습니다.
기한은 그 크롤링을 시작한 시각으로부터 [시스템] > [일반]의 "이전 문서 삭제" 일수(초깃값 ``3``\ 일) 후입니다.
기한이 지난 문서는 매분 실행되는 작업 "Doc Purger"가 인덱스에서 삭제합니다.
같은 문서가 다음 크롤링에서 다시 등록되면 기한이 연장됩니다.

따라서 다음 2가지 경우에는 문서가 검색 결과에서 사라져 버립니다.

- 작업의 실행 간격이 "이전 문서 삭제" 일수보다 긴 경우
- 변경된 항목만 읽는 증분 크롤링(Git이나 Google Drive의 ``incremental=true`` 등)에서 변경되지 않은 문서가 다시 등록되지 않는 경우

설정마다 기한을 바꾸려면 파라미터에 ``time_to_live``\ 를 분 단위로 지정합니다(예: ``time_to_live=11520``\ 으로 8일).
원본 데이터에서 삭제된 것도 이 기한이 지나야 검색 결과에서 사라집니다.
기한을 너무 길게 하면 삭제가 좀처럼 반영되지 않습니다.

결과 확인하기
=============

데이터 저장소 크롤링에서는 작업 상태가 "OK"여도 성공했다고는 할 수 없습니다.
커넥터에서 예외가 발생해도 Fess는 이를 설정 단위나 레코드 단위로 기록하고 처리를 계속합니다.
그래서 작업 로그의 상태는 "OK"가 되며, [시스템 정보] > [크롤링 정보]의 "크롤러 상태"도 바뀌지 않습니다.
다음 순서로 확인하십시오.

1. [시스템 정보] > [작업 로그]에서 작업이 종료되었는지 확인합니다. "결과"의 ``Data Config Id:`` 줄에 대상 설정 ID가 나와 있습니다
2. [시스템 정보] > [크롤링 정보]에서 해당 세션의 "인덱스 크기 (데이터 저장소)"를 확인합니다. 그 세션에서 등록한 문서 건수입니다("Default Crawler"에서는 모든 데이터 저장소의 합계)
3. [시스템 정보] > [장애 URL]에서 오류가 기록되지 않았는지 확인합니다
4. [시스템 정보] > [로그 파일]에서 ``fess-crawler.log``\ 를 다운로드하여 ERROR와 WARN 줄을 확인합니다(Docker와 RPM / DEB에서는 ``/var/log/fess/``, ZIP 패키지에서는 ``logs/``\ 에 있습니다)
5. [시스템 정보] > [검색]에서 ``label:faq``\ 처럼 검색하여 건수를 확인합니다

실패 방식에 따라 단서가 남는 곳이 다릅니다.

.. list-table::
   :header-rows: 1
   :widths: 30 35 35

   * - 상황
     - 장애 URL
     - fess-crawler.log
   * - 핸들러를 찾을 수 없음(설정 후 플러그인을 삭제한 경우 등)
     - 기록 없음
     - ``DataStore(...) is not found.``
   * - 설정 전체의 실패(커넥터가 처리를 계속할 수 없는 인증 오류나 필수 파라미터 누락 등)
     - 1건. URL 칸은 ``D<설정ID>:<설정 이름>``
     - ``Failed to process a data crawling: <설정 이름>``
   * - 레코드 단위의 실패(스크립트 평가 오류 등)
     - 레코드마다. CSV에서는 ``<파일 경로>:<행 번호>``
     - WARN 줄

CSV 커넥터에서는 ``files``\ 에 지정한 파일을 찾을 수 없는 경우나 확장자가 ``.csv`` / ``.tsv``\ 가 아닌 경우에도 오류가 되지 않습니다.
``is not found.``\ 와 ``No CSV file.``\ 의 WARN을 출력하고 0건으로 종료합니다.

[시스템 정보] > [검색]은 권한에 의한 필터링 없이 모든 문서를 표시하므로 건수 확인에 적합합니다.
반면 권한이 의도한 대로인지 확인하는 데에는 사용할 수 없습니다.
권한은 대상 이용자로 로그인한 상태(``{role}guest`` 문서라면 로그아웃한 상태)에서 일반 검색 화면으로 확인하십시오(:doc:`guide-05`).

커넥터가 전달하는 항목 이름을 모르는 경우, 크롤러의 로그 레벨을 DEBUG로 하면 가져온 값이 로그에 출력되는 커넥터가 있습니다(CSV 커넥터는 각 행의 값을 출력합니다).
설정 방법은 `데이터스토어 커넥터 개요 <https://fess.codelibs.org/ko/stable/config/datastore/ds-overview.html>`__\ 의 "디버그 설정"을 참조하십시오.
