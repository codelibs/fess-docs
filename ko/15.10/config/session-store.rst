======================
노드 간 HTTP 세션 공유
======================

개요
====

기본적으로 각 |Fess| 노드는 HTTP 세션을 자신의 메모리에 보관합니다. 로드 밸런서 뒤에서 여러 |Fess| 노드를 실행하는 경우에는 모든 노드에 환경 변수 ``FESS_SESSION_STORE=opensearch`` 를 설정하십시오. 세션은 검색 엔진의 ``fess_config.session`` 인덱스에 저장되며, 한 노드가 만든 세션을 다른 노드가 읽을 수 있습니다. 여기에는 로그인 상태와, 패스키 절차나 SSO 로그인이 두 요청 사이에 세션에 보관하는 정보가 포함됩니다(:doc:`security-passkey` 와 :doc:`sso-saml` 참조). 값을 설정하지 않았거나 비어 있거나 ``memory`` 인 경우에는 세션이 각 노드의 메모리에 보관됩니다. 알 수 없는 값은 표준 오류 출력에 보고되며 ``memory`` 로 처리됩니다.

SSO 플러그인을 추가하거나 삭제하면 저장된 모든 세션이 무효가 되는 점은 :doc:`sso-saml` 의 주의 사항을 참조하십시오.

여러 노드를 사용할 때의 전제 조건
=================================

세션을 공유하는 경우에도 로드 밸런서에서 스티키 세션(클라이언트 어피니티)을 설정하여 같은 클라이언트가 항상 같은 노드로 전달되도록 하십시오.

노드는 응답을 보내기 전에 세션을 검색 엔진에 저장하므로, 보통은 클라이언트가 응답을 받은 시점에 다른 노드가 그 세션을 읽을 수 있습니다. 그러나 이것이 보장되는 것은 아닙니다. 세션을 저장하지 못한 경우에는 노드의 로그에 경고만 기록되고 요청 자체는 정상적으로 응답됩니다. 또한 노드를 시작한 직후에는 다른 노드로 바뀐 요청이 세션을 찾지 못할 수 있습니다. 두 경우 모두, 로그인 직후처럼 다음 요청을 곧바로 다른 노드로 보내는 클라이언트는 로그인하지 않은 것으로 처리되어 ``401`` 을 받을 수 있습니다. 검증에서는 노드를 시작한 직후에 보낸 요청에서 가끔 발생했으며, 워밍업 이후에는 발생하지 않았습니다. 스티키 세션을 사용하면 클라이언트는 항상 세션을 만든 노드에 도달하므로, 공유된 세션은 그 노드를 사용할 수 없게 되었을 때 세션을 이어받는 용도로만 필요합니다.
