======================
노드 간 HTTP 세션 공유
======================

개요
====

기본적으로 각 |Fess| 노드는 HTTP 세션을 자신의 메모리에 보관합니다. 로드 밸런서 뒤에서 여러 |Fess| 노드를 실행하는 경우에는 모든 노드에 환경 변수 ``FESS_SESSION_STORE=opensearch`` 를 설정하십시오. 세션은 검색 엔진의 ``fess_config.session`` 인덱스에 저장되며, 한 노드가 만든 세션을 다른 노드가 읽을 수 있습니다. 여기에는 로그인 상태와, 패스키 절차나 SSO 로그인이 두 요청 사이에 세션에 보관하는 정보가 포함됩니다(:doc:`security-passkey` 와 :doc:`sso-saml` 참조). 값을 설정하지 않았거나 비어 있거나 ``memory`` 인 경우에는 세션이 각 노드의 메모리에 보관됩니다. 알 수 없는 값은 표준 오류 출력에 보고되며 ``memory`` 로 처리됩니다.

SSO 플러그인을 추가하거나 삭제하면 저장된 모든 세션이 무효가 되는 점은 :doc:`sso-saml` 의 주의 사항을 참조하십시오.

저장 시점과 장애 시 동작
========================

노드는 요청이 사용한 세션을 응답을 보내기 전에 검색 엔진에 저장합니다. 따라서 로그인 직후처럼 응답 직후에 다음 요청을 다른 노드로 보내는 클라이언트도 그 노드에서 세션을 찾을 수 있습니다. 응답 전송을 시작한 뒤에 이루어진 변경은 요청이 끝날 때 저장됩니다.

검색 엔진을 읽거나 쓸 수 없는 경우에도 요청에는 정상적으로 응답하며, "Failed to save the session to the session store." 또는 "Failed to load the session from the session store. The session is kept in memory only." 같은 경고가 로그에 기록됩니다(최대 1분에 1회). 이때 노드는 세션을 자신의 메모리에만 보관하며, 다시 저장할 수 있게 될 때까지 다른 노드에서는 보이지 않습니다. 로그아웃 시 저장된 세션을 삭제하지 못한 경우, 그 노드는 이후 해당 세션을 거부하지만 다른 노드는 만료될 때까지 이를 받아들입니다.

``FESS_SESSION_STORE`` 를 설정하지 않으면 각 노드는 세션을 자신의 메모리에만 보관하며, 다른 노드로 전달된 클라이언트는 그 노드에서 로그인하지 않은 상태가 됩니다. 위에서 설명한 대로 세션을 공유하거나, 로드 밸런서가 같은 클라이언트를 항상 같은 노드로 보내도록 하십시오.
