======================
在节点之间共享HTTP会话
======================

概述
====

默认情况下，每个 |Fess| 节点将HTTP会话保存在自己的内存中。在负载均衡器之后运行多个 |Fess| 节点时，请在每个节点上设置环境变量 ``FESS_SESSION_STORE=opensearch``。会话随后保存在搜索引擎的 ``fess_config.session`` 索引中，一个节点可以读取另一个节点创建的会话。其中包括登录状态，以及通行密钥操作或SSO登录在两次请求之间保存在会话中的信息（请参阅 :doc:`security-passkey` 和 :doc:`sso-saml`）。未设置值、值为空或为 ``memory`` 时，会话保留在各节点的内存中。未知的值会输出到标准错误输出，并按 ``memory`` 处理。

关于添加或删除SSO插件会使所有已保存的会话失效，请参阅 :doc:`sso-saml` 中的说明。

保存时机与故障时的行为
======================

节点在发送响应之前，会将请求所涉及的会话保存到搜索引擎。因此，在登录之后等响应刚结束就向其他节点发送下一次请求的客户端，也能在该节点上找到会话。响应开始发送之后所做的更改，会在请求结束时保存。

无法读取或写入搜索引擎时，请求仍会正常响应，并在日志中记录“Failed to save the session to the session store.”或“Failed to load the session from the session store. The session is kept in memory only.”之类的警告（最多每分钟一次）。此时节点只在自己的内存中保留该会话，在能够再次保存之前，其他节点看不到它。注销时无法删除已保存的会话时，该节点此后会拒绝该会话，但其他节点在会话过期之前仍会接受它。

未设置 ``FESS_SESSION_STORE`` 时，每个节点只在自己的内存中保存会话，被分配到其他节点的客户端在该节点上处于未登录状态。请按上文共享会话，或让负载均衡器始终将同一客户端分配到同一节点。
