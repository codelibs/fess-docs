==============================
ノード間でのHTTPセッション共有
==============================

概要
====

デフォルトでは、各 |Fess| ノードはHTTPセッションを自身のメモリに保持します。ロードバランサーの背後で複数の |Fess| ノードを動かす場合は、すべてのノードに環境変数 ``FESS_SESSION_STORE=opensearch`` を設定してください。セッションは検索エンジンの ``fess_config.session`` インデックスに保存され、あるノードが作成したセッションを別のノードが読み取れます。対象には、ログイン状態のほか、パスキーの操作やSSOのログインが2つのリクエストの間にセッションへ保持する情報が含まれます（ :doc:`security-passkey` と :doc:`sso-saml` を参照）。値を設定しない場合、空の場合、または ``memory`` の場合は、セッションは各ノードのメモリに保持されます。不明な値は標準エラー出力に報告され、 ``memory`` として扱われます。

SSOプラグインを追加または削除すると保存済みのセッションがすべて無効になる点については、 :doc:`sso-saml` の注記を参照してください。

保存のタイミングと障害時の動作
==============================

ノードは、リクエストが操作したセッションを、レスポンスを送る前に検索エンジンへ保存します。そのため、ログイン直後などレスポンスの直後に次のリクエストを別のノードへ送るクライアントも、そのノードでセッションを見つけられます。レスポンスの送信を始めた後に行われた変更は、リクエストの終了時に保存されます。

検索エンジンを読み書きできない場合も、リクエストには通常どおり応答し、「Failed to save the session to the session store.」や「Failed to load the session from the session store. The session is kept in memory only.」といった警告をログに出力します（最大で1分に1回）。このときノードはセッションを自身のメモリにだけ保持し、再び保存できるようになるまで、ほかのノードからは見えません。ログアウトで保存済みのセッションを削除できなかった場合、そのノードは以降そのセッションを拒否しますが、ほかのノードは有効期限が切れるまで受け付けます。

``FESS_SESSION_STORE`` を設定しない場合、各ノードはセッションを自身のメモリにだけ保持し、別のノードへ振り分けられたクライアントはそのノードではログインしていない状態になります。上記のとおりセッションを共有するか、ロードバランサーで同じクライアントを同じノードに振り分けてください。
