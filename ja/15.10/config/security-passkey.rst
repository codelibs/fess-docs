==================================
パスキー（WebAuthn）ログインの設定
==================================

概要
====

|Fess| は、ローカルユーザー（管理画面の「ユーザー」で作成したユーザー）が、パスワードの代わりにパスキー（WebAuthn）でログインする機能を備えています。15.10 で追加された機能で、既定では無効です。

- パスワードとパスキーのどちらでもログインできます。両方を要求する多要素認証ではありません。
- 対象は ``fess_user`` インデックスのローカルユーザーだけです。LDAP と SSO のユーザーはパスキーを登録できません。パスキーでのログインは LDAP に問い合わせません。
- |Fess| が保存するのは、パスキーの公開鍵と名前などです。秘密鍵は利用者の認証器（ブラウザ、OS、セキュリティキーなど）の中にあり、|Fess| には渡りません。

設定
====

パスキーの設定は ``fess_config.properties`` に書きます（ZIP 版は ``app/WEB-INF/classes/fess_config.properties`` 、RPM/DEB 版は ``/etc/fess/fess_config.properties`` ）。管理画面の「システム」→「全般」には項目がなく、 ``system.properties`` には書けません。変更を反映するには |Fess| の再起動が必要です。Docker 版では、 ``FESS_JAVA_OPTS`` の ``-Dfess.config.passkey.enabled=true`` のように指定できます（ :doc:`../install/install-docker` を参照）。

.. list-table::
   :header-rows: 1
   :widths: 22 18 60

   * - キー
     - 既定値
     - 説明
   * - ``passkey.enabled``
     - ``false``
     - パスキーでのログインを有効にします。 ``true`` にしても、下の ``passkey.rp.id`` と ``passkey.origins`` が使える値でなければ、機能は無効のままです。
   * - ``passkey.rp.id``
     - （空）
     - リライングパーティー ID。パスキーを結びつけるドメインです（例: ``example.com`` ）。パスキーは、このホストとそのサブドメインでだけ使えます。
   * - ``passkey.rp.name``
     - ``Fess``
     - パスキーを作るときにブラウザが表示するリライングパーティーの名前です。
   * - ``passkey.origins``
     - （空）
     - パスキーの操作を受け付けるオリジンのリスト（カンマ区切り）です（例: ``https://fess.example.com`` ）。各項目はホスト名を持つ ``http`` または ``https`` のオリジンにします。

有効にする設定の例です。
::

    passkey.enabled=true
    passkey.rp.id=example.com
    passkey.rp.name=Fess
    passkey.origins=https://fess.example.com

- ``passkey.rp.id`` は、すべてのパスキーが結びつくドメインです。登録後に変更すると、登録済みのパスキーはすべて使えなくなります。利用者は新しい ID で登録し直す必要があるため、最初に決めてください。 ``passkey.origins`` に書くオリジンのホストは、 ``passkey.rp.id`` と同じか、そのサブドメインにします。
- ``passkey.origins`` には、利用者がブラウザで |Fess| を開くときのオリジン（スキーム、ホスト、ポート）を、そのまま書きます。リバースプロキシの内側のアドレスではありません。ここにないオリジンからのパスキーの操作は拒否されます。

機能が無効のままになるとき
--------------------------

``passkey.enabled=true`` でも、次の場合、パスキーは **画面にエラーを出さずに無効のまま** になります。ログイン画面にパスキーのボタンは表示されず、 ``/api/v2/auth/passkey`` 以下の API は ``404`` を返し、 ``/api/v2/ui/config`` の ``features.passkey_enabled`` は ``false`` です。原因は ``fess.log`` の警告で確認します。同じ警告は起動後に 1 回だけ出力されます。

- ``passkey.rp.id`` または ``passkey.origins`` が空: ``passkey.enabled is true but passkey.rp.id or passkey.origins is empty, so passkeys are disabled.``
- ``passkey.origins`` に項目がない: ``passkey.enabled is true but passkey.origins holds no origin, so passkeys are disabled.``
- ``passkey.origins`` に、 ``http`` または ``https`` のオリジンではない項目（ホスト名のない値や別のスキームなど）がある: ``passkey.origins holds an entry that is not an http or https origin, so passkeys are disabled: entry=...``

``passkey.origins`` が使える値でも、利用者が開いているオリジンがその中になければ、パスキーの登録とログインはすべて拒否されます。利用者の画面には理由が表示されないため、 ``fess.log`` に出力される警告を見てください。 ``A passkey response came from an origin that is not in passkey.origins: origin=...`` に、拒否されたオリジンと設定値が出ます（最初の 1 件だけ）。そのオリジンを ``passkey.origins`` に追加します。

使い方
======

ログイン
--------

パスキーが有効で、ブラウザが WebAuthn に対応していれば、検索画面のログインと、管理画面のログイン画面に「パスキーでログイン」のボタンが表示されます。ボタンを押すとブラウザが認証器を求め、ユーザー名を入力しなくてもログインできます。

パスキーでのログインは、パスワードでのログインと同じ IP アドレスごとの回数制限（ ``theme.api.login.*`` ）を使います。失敗は回数に数えられ、成功すると戻ります（ :doc:`rate-limiting` を参照）。失敗の理由は画面には表示されず、パスワードを間違えたときと同じメッセージになります。

パスキーの登録と削除
--------------------

ローカルユーザーは、検索画面のユーザーメニューの「パスワード変更」（ ``/profile`` ）にある「パスキー」で、自分のパスキーを登録・削除できます。

1. パスキーの名前（64 文字以内）と現在のパスワードを入力し、「パスキーを登録」を押します。
2. ブラウザの案内に従って、認証器でパスキーを作ります。

- 登録のたびに、現在のパスワードの入力が必要です。LDAP のユーザー名とパスワードとしても受け付けられるローカルユーザーは、どちらのアカウントのパスワードを確認したのか区別できないため、パスキーを登録できません。
- 1 人のユーザーが登録できるパスキーは 20 件までです。
- パスキーがなく、登録もできないユーザー（LDAP や SSO のユーザー、ブラウザが WebAuthn に対応していない場合）には、「パスキー」の欄は表示されません。
- パスキーを削除すると、そのユーザーの **ほかのログインセッションは終了** します。紛失した認証器で開いたセッションを残さないためで、パスワードを変更したときと同じ仕組みです（下の「パスワードとの関係」を参照）。削除を行ったセッションは終了しません。

管理者の操作
------------

管理画面の「ユーザー」の詳細画面には、そのユーザーの「パスキー」の一覧（ラベル、作成日時、最終使用日時）が表示されます。管理者はパスキーを登録できませんが、編集権限があれば、パスキーごとに「リセット」で削除できます。ユーザーが認証器を失ったときの対応に使います。リセットすると、ユーザーは新しいパスキーを登録し直せます。リセットした場合も、そのユーザーのログインセッションは終了します（下の「パスワードとの関係」を参照）。

``passkey.enabled`` を ``false`` に戻した後も、登録済みのパスキーがあるユーザーの詳細画面には一覧が表示され、削除できます。パスキーのデータは、機能を無効にしても消えません。

パスワードとの関係
==================

- パスキーとパスワードは別の資格情報です。ユーザーのパスワードを変更しても、管理者がパスワードを設定し直しても、登録済みのパスキーは削除されず、引き続きログインに使えます。
- パスワードが変更されると、そのユーザーの他のログインセッションは終了します（ :doc:`../install/security` を参照）。パスキーで開いたセッションも同じです。各セッションは ``password.changed.check.interval`` 秒（既定値 ``60`` ）に 1 回までの間隔で確認するため、その時間内に終了します。
- パスキーを削除したときも、同じ仕組みでほかのセッションが終了します（上記）。

ユーザーの削除と名前の変更
==========================

パスキーは、ユーザー名だけで結びついています。そのため、同じ名前の別のユーザーが引き継がないように、次のときにパスキーも削除されます。

- ユーザーを削除したとき。
- ユーザーを作成したとき（同じ名前のパスキーが残っていれば削除します）。
- ユーザーの名前を変更したとき（変更前と変更後の名前の両方のパスキーを削除します）。パスキーは名前の変更に付いていかないため、利用者は登録し直します。すでに別のユーザーが使っている名前への変更は、パスキーを削除する前に拒否されます。

保存先とバックアップ
====================

パスキーは、インデックス ``fess_user.passkey`` に保存されます（接頭辞は ``index.user.index`` で、既定は ``fess_user`` です）。このインデックスは、パスキーが無効でも |Fess| の起動時に作られ、ユーザーの削除や名前の変更、管理画面のユーザー詳細で使われます。インデックスの作成を許可していない環境では、アップグレードの前に作成してください（ :ref:`upgrade-1510-passkey` を参照）。

このインデックスは ``fess_user`` のエイリアスに含まれないため、管理画面の「バックアップ」の ``fess_user.bulk`` にパスキーは含まれません。バックアップから復元した場合、利用者はパスキーを登録し直します。

動作環境
========

- **HTTPS** : ブラウザは WebAuthn を、安全なコンテキスト（HTTPS、または ``localhost`` ）でしか使えません。 |Fess| は ``passkey.origins`` に ``http`` のオリジンも受け付けますが、本番環境では HTTPS で |Fess| を公開し、 ``https://`` のオリジンを指定してください（ :doc:`../install/security` の「HTTPS の有効化」を参照）。
- **ブラウザ** : WebAuthn の API（ ``PublicKeyCredential`` ）を提供するブラウザが必要です。提供しないブラウザでは、ログインのボタンも、パスキーの登録欄も表示されません。
- **認証器** : 常駐（discoverable）資格情報と、ユーザー検証（PIN や生体認証など）に対応しているものが必要です。 |Fess| はこの 2 つを必須として要求し、署名アルゴリズムは ES256 と RS256、認証器の証明書（attestation）は使いません。
- **複数ノード** : パスキーの操作中のチャレンジは HTTP セッションに 5 分間保持されます。ロードバランサーの背後で複数のノードを動かす場合は、ノード間でセッションを共有する（環境変数 ``FESS_SESSION_STORE=opensearch`` ）か、ロードバランサーで同じセッションを同じノードに固定してください。

API
===

パスキーの API は ``/api/v2/auth/passkey`` 以下にあります。パスキーが無効の間は、すべて ``404`` を返します。機能が使えるかどうかは、 ``/api/v2/ui/config`` の ``features.passkey_enabled`` で分かります（ :doc:`../api/api-uiconfig` を参照）。

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - エンドポイント
     - 説明
   * - ``POST /api/v2/auth/passkey/login/options``
     - ログインのオプション（チャレンジ）を取得します。
   * - ``POST /api/v2/auth/passkey/login/verify``
     - 認証器の応答を検証してログインします。
   * - ``GET /api/v2/auth/passkey``
     - ログイン中のユーザーのパスキーの一覧と、登録できるかどうか（ ``can_register`` ）を返します。
   * - ``POST /api/v2/auth/passkey/register/options``
     - 現在のパスワード（ ``current_password`` ）を確認して、登録のオプションを取得します。
   * - ``POST /api/v2/auth/passkey/register/verify``
     - 名前（ ``label`` ）と認証器の応答を検証して、パスキーを登録します。
   * - ``DELETE /api/v2/auth/passkey/{credentialId}``
     - ログイン中のユーザーのパスキーを削除します。

``register`` と削除には ``X-Fess-CSRF-Token`` ヘッダーが必要です。ログインの 2 つは、 ``/api/v2/auth/login`` と同じく CSRF トークンを必要としません。

トラブルシューティング
======================

パスキーのボタンが表示されない
------------------------------

- ``/api/v2/ui/config`` の ``features.passkey_enabled`` を確認します。 ``false`` の場合は、 ``fess.log`` の警告で、設定が使える値かを確認してください（上の「機能が無効のままになるとき」）。
- 変更後に |Fess| を再起動したかを確認します。
- ブラウザが WebAuthn に対応しているか、HTTPS（または ``localhost`` ）で開いているかを確認します。
- 同梱のテーマ以外を使っている場合は、そのテーマがパスキーのボタンに対応している必要があります。

登録やログインが失敗する
------------------------

- ``fess.log`` に ``is not in passkey.origins`` の警告が出ていれば、 ``passkey.origins`` に、ブラウザで開いているオリジンを追加します。
- ``passkey.rp.id`` を変更した後は、変更前に登録したパスキーは使えません。古いパスキーを削除して、登録し直してください。
