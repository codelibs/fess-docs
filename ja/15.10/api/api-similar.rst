===================
類似ドキュメントAPI
===================

このドキュメントでは、指定したドキュメントと内容が同じドキュメントを一覧する |Fess| の v2 類似ドキュメント API について説明します。共通のレスポンスエンベロープ・エラーモデルについては :doc:`api-overview` を参照してください。

ベースURLは ``http://<Server Name>/api/v2/`` です（ローカル環境の例: ``http://localhost:8080/api/v2`` ）。

.. note::

   この API が見つけるのは、コピーや内容がほぼ同じドキュメントです。話題が似ているだけのドキュメントは見つかりません（後述の「返されるドキュメント」を参照）。

類似ドキュメントの取得
======================

リクエスト
----------

==================  ====================================================
HTTPメソッド        GET
エンドポイント      ``/api/v2/documents/{docId}/similar``
==================  ====================================================

``docId`` のドキュメントと同じ内容の署名を持つドキュメントを返します。検索結果の横に「類似ドキュメント」へのリンクを出すために使えます。

- 指定したドキュメントにも返されるドキュメントにも、 ``/api/v2/search`` と同じロールフィルター・仮想ホストフィルター・追加クエリが適用されます。存在しないドキュメントと、呼び出し元から見えないドキュメントは、どちらも ``not_found`` (404) になります。指定したドキュメント自身と、同じ URL のドキュメントは返されません。
- ``login.required=true`` のとき、ログインしていない呼び出し元は ``auth_required`` (401) になります。アクセストークンは ``/api/v2/search`` と同じ方法で使えます。
- リクエストは ``api.search.similar.rate.limit.per.minute`` （デフォルト: ``30`` 、 ``0`` は無制限）回/分に制限され、ログインユーザーごと、ゲストはクライアント IP ごとに数えます。上限を超えると ``429`` と ``Retry-After`` ヘッダーが返ります。
- 返されるのは1ページだけで、URL、ドキュメント ID の順に並びます。 ``start`` やオフセットのパラメーターはありません。

返されるドキュメント
--------------------

|Fess| は、ドキュメントを索引に登録するときに内容の署名（ ``content_minhash_bits`` ）を計算します。この API は、指定したドキュメントと署名が同じドキュメントを返します。重複文書レポート（ :doc:`../admin/docreport-guide` ）、検索パラメーター ``sdh`` 、 ``similar_docs_*`` フィールドと同じグループ分けですが、重複結果の折り畳みを有効にしなくても使えます。

- 返されるのは、コピーや内容がほぼ同じドキュメントです。署名が変わるほど内容を編集したドキュメントは返されないため、話題が似たドキュメントを探す機能ではありません。
- 指定したドキュメントに内容や語がない場合と、検索エンジンが CodeLibs のプラグインなしで動作している場合（ ``search_engine.type`` が ``vanilla`` ・ ``aws`` ・非推奨の ``cloud`` 。 :doc:`../config/search-engine-type` を参照）は、エラーではなく ``data`` が空の配列になります。

リクエストパラメーター
----------------------

.. tabularcolumns:: |p{4cm}|p{11cm}|
.. list-table:: リクエストパラメーター
   :widths: 27 73
   :header-rows: 1

   * - パラメーター
     - 説明
   * - ``docId``
     - ドキュメントの識別子（パス、必須、パターン ``[A-Za-z0-9_-]{1,512}`` ）。一致しない値は ``invalid_request`` (400) になります。
   * - ``num``
     - 返すドキュメント数（クエリ、デフォルト ``10`` ）。 ``20`` と ``paging.search.page.max.size`` のどちらか小さいほうを超える値は、その値に切り詰められ、レスポンスの ``page_size`` で確認できます。 ``0`` 以下は ``invalid_request`` (400) になります。数値でない値は無視され、デフォルト値が使われます。

レスポンス
----------

成功時（HTTP 200）には、共通エンベロープの ``response`` 直下に以下のフィールドが返ります。

::

    {
      "response": {
        "status": 0,
        "doc_id": "a1b2c3d4e5f6",
        "exec_time": "0.01",
        "query_time": 5,
        "page_size": 10,
        "record_count": 1,
        "record_count_relation": "EQUAL_TO",
        "partial": false,
        "timed_out": false,
        "shard_failed": false,
        "data": [
          {
            "doc_id": "f6e5d4c3b2a1",
            "url": "https://example.com/copy/",
            "title": "Example",
            "content_description": "An example document about Fess."
          }
        ]
      }
    }

各フィールドは以下のとおりです。

.. tabularcolumns:: |p{4cm}|p{11cm}|
.. list-table:: レスポンスフィールド
   :widths: 27 73
   :header-rows: 1

   * - フィールド
     - 説明
   * - ``doc_id``
     - 指定したドキュメントの ID。
   * - ``exec_time``
     - 実行時間（秒）。 ``"0.01"`` のような小数の文字列。
   * - ``query_time``
     - 検索エンジンのクエリ時間（int64、ミリ秒）。
   * - ``page_size``
     - 上記の上限を適用したあとの、要求したドキュメント数。
   * - ``record_count``
     - 署名が同じドキュメントの件数（ ``data`` に含まれない分も含む）。正確な件数を数えるのは ``query.track.total.hits`` （デフォルト: ``10000`` ）までです。
   * - ``record_count_relation``
     - ``EQUAL_TO`` のとき件数は正確で、 ``GREATER_THAN_OR_EQUAL_TO`` のときは下限だけが分かります。
   * - ``partial``
     - 結果が不完全な可能性があるか（bool）。検索と同様にクエリタイムアウト（ ``query.timeout`` ）が適用されます。
   * - ``timed_out``
     - クエリタイムアウトに達したか（bool）。
   * - ``shard_failed``
     - 1つ以上のシャードが失敗したか（bool）。
   * - ``data``
     - ドキュメントの配列（URL、ドキュメント ID の順）。各要素は ``/api/v2/search`` のヒットと同じフィールドを持ち（ :doc:`api-search` を参照）、 ``tags`` （呼び出し元から見えるタグ。 :doc:`api-tag` を参照）も含みます。ハイライトするクエリがないため、 ``content_description`` は本文のダイジェストで、 ``score`` はありません。

表: レスポンスフィールド

エラーレスポンス
----------------

.. tabularcolumns:: |p{4cm}|p{11cm}|
.. list-table:: エラーレスポンス
   :widths: 25 75
   :header-rows: 1

   * - ステータスコード
     - 説明
   * - 400 Bad Request
     - ``docId`` がパターンに一致しない、または ``num`` が ``0`` 以下の場合。
   * - 401 Unauthorized
     - 認証が必要な場合（ログイン必須の設定が有効でログインしていない、または登録されていない・期限切れのアクセストークンが指定された）。
   * - 404 Not Found
     - 指定したドキュメントが存在しない、または呼び出し元から見えない場合（ ``not_found`` ）。
   * - 405 Method Not Allowed
     - 許可されていない HTTP メソッドが指定された場合。
   * - 429 Too Many Requests
     - 1分あたりのリクエスト数の上限を超えた場合。 ``Retry-After`` ヘッダーに待つ秒数（ ``60`` ）が入ります。
   * - 500 Internal Server Error
     - サーバー内部エラーが発生した場合。
   * - 503 Service Unavailable
     - 検索エンジンがリクエストを受け付けられなかった場合（到達できない、または容量不足で拒否された）。 ``error.code`` は ``service_unavailable`` で、 ``Retry-After`` ヘッダーに待つ秒数（ ``5`` ）が入ります。リクエスト自体に問題はないため、少し待って再試行してください。
