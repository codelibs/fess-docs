==============================================
Web サイトとファイルサーバーをまとめて検索する
==============================================

はじめに
========

社内の資料は、ポータルサイト、部門の共有フォルダー、古い資料を置いたアーカイブ用のディレクトリなどに分かれて置かれがちです。
探す人は、どこにあるかを思い出してから、それぞれの場所で別々に探すことになります。

本記事では、Fess 15.9 で次の 3 か所をクロールし、1 つの検索窓から探せるようにします。
検索画面では、ラベルを使って「ポータルだけ」「共有フォルダーだけ」のように絞り込めるようにします。

- 社内ポータル（Web サイト）
- Windows ファイルサーバーの共有フォルダー（SMB）
- サーバー上のアーカイブ用ディレクトリ（ローカルのファイル）

手順は :doc:`guide-02` で起動した Docker 環境（``fess01`` と ``search01``）を前提にしています。
Google Drive・SharePoint・Box などのクラウドストレージは :doc:`guide-07` で扱います。
ファイルサーバー検索を導入する前の確認事項は :doc:`file-server-search` にまとめています。

この記事で作る構成
==================

.. list-table::
   :header-rows: 1
   :widths: 18 40 14 28

   * - 対象
     - クロールするパス
     - ラベルの値
     - クロールの実行
   * - 社内ポータル
     - ``https://portal.example.com/``
     - ``portal``
     - 毎日 2:00
   * - 共有フォルダー
     - ``smb://fileserver.example.com/shared/``
     - ``shared``
     - 毎日 3:00
   * - アーカイブ
     - ``file:/data/archive/``\ （ホストの ``/srv/archive``）
     - ``archive``
     - 毎週日曜 4:00

ホスト名とディレクトリは例です。
自分の環境に合わせて読み替えてください。
共有フォルダーを読み取れるサービスアカウント（読み取り専用で十分です）と、``fess01`` コンテナからファイルサーバーの SMB のポート（445）に接続できることが前提です。

ラベルはクロールのときに付くため、クロール設定より先に作ります。
この記事の見出しの順に進めてください。

アーカイブ用ディレクトリをコンテナから読めるようにする
======================================================

docker-fess v15.9.0 の ``compose.yaml`` では、``fess01`` にボリュームが定義されていません。
そのため、ホストの ``/srv/archive`` は、そのままではコンテナの中から見えません。
``compose.yaml`` の ``fess01`` に ``volumes`` を追加し、あわせて ``environment`` に ``FESS_JAVA_OPTS`` の行を加えます。

.. code-block:: yaml

    services:
      fess01:
        image: ghcr.io/codelibs/fess:15.9.0
        container_name: fess01
        environment:
          - "SEARCH_ENGINE_HTTP_URL=http://search01:9200"
          - "FESS_DICTIONARY_PATH=${FESS_DICTIONARY_PATH:-/usr/share/opensearch/config/dictionary/}"
          - "FESS_JAVA_OPTS=-Duser.timezone=Asia/Tokyo -Dfess.system.day.for.cleanup=10"
        volumes:
          - /srv/archive:/data/archive:ro
        # ports 以降は元のまま

- ``/srv/archive:/data/archive:ro`` は、ホストの ``/srv/archive`` をコンテナの ``/data/archive`` に読み取り専用でマウントします
- ``-Duser.timezone=Asia/Tokyo`` は、後で設定するジョブの実行時刻を日本時間で扱うための指定です。compose.yaml にもイメージにもタイムゾーンの指定がないため、指定しないとジョブが日本時間からずれた時刻に動きます
- ``-Dfess.system.day.for.cleanup=10`` は、文書の有効期限（日数）の既定値を 10 日にします。理由は後の「週 1 回のジョブと文書の有効期限」で説明します

変更したら、コンテナを作り直します。

::

    $ docker compose -f compose.yaml -f compose-opensearch3.yaml up -d

``fess01`` が作り直されるため、それまでに［システム］>［全般］で変更した設定は消えます（:doc:`guide-02` の「停止と再開」を参照）。
［全般］を変更する作業は、この手順の後に行ってください。

コンテナの中の Fess はユーザー ``fess``\ （UID 1001）で動いています。
このユーザーでファイルの一覧が見えることを確かめます。

::

    $ docker compose -f compose.yaml -f compose-opensearch3.yaml exec -u fess fess01 ls /data/archive

``Permission denied`` になる場合は、ホスト側の ``/srv/archive`` 以下を UID 1001 から読めるようにしてください（たとえば、その他のユーザーに読み取りと、ディレクトリへの実行の権限を付けます）。

ラベルを作る
============

ラベルは、文書の URL が正規表現に一致したときに付きます。
クロール設定の画面にはラベルを選ぶ項目がない（既定では表示されない）ため、ラベル側の「対象とするパス」で付ける範囲を指定します。

［クローラー］>［ラベル］>［新規作成］で、次の 3 つを作ります。

.. list-table::
   :header-rows: 1
   :widths: 18 14 68

   * - 名前
     - 値
     - 対象とするパス
   * - ポータル
     - ``portal``
     - ``https://portal.example.com/.*``
   * - 共有フォルダー
     - ``shared``
     - ``smb://fileserver.example.com/shared/.*``
   * - アーカイブ
     - ``archive``
     - ``file:/data/archive/.*``

- 「名前」は検索画面に表示される文字列で、日本語を使えます
- 「値」は英数字とアンダースコアだけが使えます（ハイフンや日本語は入力エラーになります）
- 「対象とするパス」は URL 全体に一致する必要があるため、末尾の ``.*`` を省かないでください。空のままにすると、そのラベルはどの文書にも付きません
- 「パーミッション」には ``{role}guest`` が入っています。ログインしていない利用者にもラベルが表示されるので、そのままにします

ラベルを作る前にクロールした文書には、ラベルが付いていません。
後からラベルを追加・変更した場合は、もう一度クロールするか、［システム］>［スケジューラ］の「Label Updater」を［今すぐ開始］で実行して、既存の文書に反映します。

クロール設定を作る
==================

社内ポータル（Web クロール）
----------------------------

［クローラー］>［ウェブ］>［新規作成］で、次の項目を入力して［作成］をクリックします。

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - 項目
     - 値
   * - 名前
     - ``社内ポータル``
   * - URL
     - ``https://portal.example.com/``
   * - クロール対象とするURL
     - ``https://portal.example.com/.*``
   * - クロール対象から除外するURL
     - 既に入っている行の下に ``https://portal.example.com/admin/.*`` を追加

「クロール対象から除外するURL」には、画像や CSS などを除外する正規表現が最初から入っています。
消さずに、行を追加してください。
「スレッド数」は ``1``、「間隔」は ``10000`` ミリ秒が初期値で、ポータルへの負荷を抑えた設定です。

共有フォルダー（SMB）とファイル認証
-----------------------------------

まず［クローラー］>［ファイルシステム］>［新規作成］で、次の設定を作ります。

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - 項目
     - 値
   * - 名前
     - ``共有フォルダー``
   * - パス
     - ``smb://fileserver.example.com/shared/``
   * - クロール対象とするパス
     - ``smb://fileserver.example.com/shared/.*``
   * - クロール対象から除外するパス
     - ``.*\.tmp$``

ファイルクロールの初期値は、「スレッド数」が ``5``、「間隔」が ``1000`` ミリ秒です。

続いて、この設定にサービスアカウントを結び付けます。
ファイル認証は、ファイルクロール設定を選んで作る仕組みです。
ファイルクロール設定が 1 つもないうちは、［ファイル認証］の画面に［新規作成］が表示されません。

［クローラー］>［ファイル認証］>［新規作成］で、次の項目を入力して［作成］をクリックします。

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - 項目
     - 値
   * - ホスト名
     - ``fileserver.example.com``\ （パスに書いたホスト名と同じ表記）
   * - ポート
     - 空欄
   * - スキーム
     - ``Samba``
   * - ユーザー名・パスワード
     - サービスアカウントのもの
   * - パラメーター
     - ドメインのアカウントなら ``domain=EXAMPLE`` のようにドメイン名を指定
   * - ファイルクロール設定
     - ``共有フォルダー``

「ホスト名」は、パスのホスト名と文字どおり一致している必要があります。
パスを IP アドレスで書いた場合は、ここにも IP アドレスを書きます。
「ポート」を空欄にした認証は、``smb://ホスト名/共有名/`` のようにポートを書いていないパスに使われます。

.. note::

   SMB でクロールしたファイルには、既定でファイルのアクセス権（ACL）から作ったロールが付き、クロール設定の「パーミッション」に追加されます。
   「パーミッション」に初期値の ``{role}guest`` が残っている間は、ログインしていない利用者を含めて全員が検索できます。
   アクセス権に合わせて検索結果を出し分ける場合は、:doc:`file-server-search` と :doc:`guide-05` を参照してください。

アーカイブ（ローカルのファイル）
--------------------------------

［クローラー］>［ファイルシステム］>［新規作成］で、次の設定を作ります。
パスはコンテナの中のパスで指定します。

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - 項目
     - 値
   * - 名前
     - ``アーカイブ``
   * - パス
     - ``file:/data/archive/``
   * - クロール対象とするパス
     - ``file:/data/archive/.*``
   * - クロール対象から除外するパス
     - ``.*\.(log|bak)$``

ローカルのファイルは ``file:/data/archive/`` のように、``file:`` の後にスラッシュ 1 つで書きます。
クローラーが見つけたファイルの URL は ``file:/data/archive/2020/report.pdf`` の形になり、「クロール対象とするパス」はこの URL に対して照合されます。
``file:///data/archive/.*`` と書くと、どのファイルにも一致せず、1 件も登録されません。

設定ごとにジョブを作る
======================

スケジューラの「Default Crawler」は、有効なクロール設定をまとめて毎日 0:00 に実行します。
対象ごとに実行時刻を変えるには、クロール設定ごとにジョブを作ります。

1. ［クローラー］>［ウェブ］で「社内ポータル」をクリックし、詳細画面の［新しいジョブの作成］をクリックします
2. ジョブの作成画面が開き、「名前」に ``Web Crawler - 社内ポータル``、「スクリプト」にこの設定だけをクロールする内容が入っています
3. 「スケジュール」は空なので、cron 式を入力して［作成］をクリックします
4. ［クローラー］>［ファイルシステム］の「共有フォルダー」「アーカイブ」でも同じ操作をします（名前は ``File Crawler - 共有フォルダー`` のようになります）

.. list-table::
   :header-rows: 1
   :widths: 40 25 35

   * - ジョブ
     - スケジュール
     - 意味
   * - ``Web Crawler - 社内ポータル``
     - ``0 2 * * *``
     - 毎日 2:00
   * - ``File Crawler - 共有フォルダー``
     - ``0 3 * * *``
     - 毎日 3:00
   * - ``File Crawler - アーカイブ``
     - ``0 4 * * 0``
     - 毎週日曜 4:00

cron 式は「分 時 日 月 曜日」の順で、曜日の ``0`` は日曜日です。

最後に、「Default Crawler」が同じ設定を 0:00 にもう一度クロールしないようにします。
［システム］>［スケジューラ］で「Default Crawler」をクリックし、［編集］で「スケジュール」を空にして［更新］をクリックします。
「状態」の「有効」を外さずにおけば、すべての設定をまとめてクロールしたいときに［今すぐ開始］で実行できます（無効にすると［今すぐ開始］が表示されなくなります）。

週 1 回のジョブと文書の有効期限
-------------------------------

クロールで登録された文書には有効期限が付き、期限を過ぎると「Doc Purger」ジョブ（毎分実行）がインデックスから削除します。
有効期限は、クロールを始めた時刻から［システム］>［全般］の「以前のドキュメントを削除」の日数後で、初期値は ``3`` 日です。
次のクロールで同じファイルが見つかれば、有効期限は延長されます。

初期値のままだと、日曜にしかクロールしないアーカイブの文書は、水曜には検索できなくなります。
そのため、この日数を最も長いクロール間隔（7 日）より大きくする必要があります。
本記事では、ジョブが 1 回失敗しても消えないように余裕を見て ``10`` 日にしています。

- Docker 環境では、前述の ``-Dfess.system.day.for.cleanup=10`` がこの初期値になります。［全般］の値は ``fess01`` を作り直すと消えるため、compose.yaml に書いておくほうが確実です
- Docker 以外の環境では、［全般］の「以前のドキュメントを削除」を ``10`` にして［更新］をクリックします

この日数を延ばすと、ファイルサーバーから削除されたファイルも、最後に見つかったクロールから最大でその日数の間は検索結果に残ります。

実行して結果を確かめる
======================

ジョブを実行する
----------------

翌日まで待たずに、［システム］>［スケジューラ］から 3 つのジョブを順にクリックし、それぞれ［今すぐ開始］をクリックします。

完了を確かめる
--------------

1. ［システム情報］>［ジョブログ］で、3 つのジョブの「状態」が「実行中」から「OK」になるのを待ちます。「失敗」の場合は行をクリックし、「結果」を確認します
2. ［システム情報］>［クロール情報］で、各セッションの「インデックスのサイズ (ウェブ/ファイル)」を見て、登録件数が想定に近いかを確かめます
3. 件数が少ない場合は、［システム情報］>［障害URL］を開きます。取得できなかった URL と、エラーの種別とログが記録されています

よくある原因は次のとおりです。

- 共有フォルダーが 0 件で、障害URL に共有のパスが記録されている: ファイル認証の「ホスト名」とパスの表記、「ファイルクロール設定」の選択、パスワードを見直します。ログに接続のエラーが出ている場合は、コンテナからファイルサーバーの名前が引けるか、445 番ポートに届くかを確かめます
- アーカイブが 0 件で、障害URL も空: パスを ``file:///`` で書いていないか、「クロール対象とするパス」がパスと同じ形かを見直します
- アーカイブで読み取りのエラーが出る: 前述の ``exec -u fess`` のコマンドで、コンテナからファイルが読めるかを確かめます

ラベルで絞り込む
----------------

``http://localhost:8080/`` で、3 か所すべてに含まれていそうな語を検索します。
結果には、ポータルのページ、共有フォルダーの Office 文書、アーカイブの PDF などが関連度の順に混ざって並びます。

ラベルによる絞り込みは、15.9 の検索画面（テーマ ``bootstrap``）では 2 か所にあります。

- 検索結果の横に表示される「ラベル」の一覧: 結果に含まれるラベルが件数つきで並び、クリックするとそのラベルに絞り込まれます
- 検索窓の右にある歯車のボタン: 「検索オプション」が開き、「ラベル」の一覧から 1 つ以上を選んで［検索］をクリックします。複数を選ぶと、いずれかのラベルが付いた文書が対象になり、何も選ばなければ全体が対象です

絞り込んだときの URL には ``fields.label=shared`` のようなパラメーターが付きます。
検索結果の横に「ラベル」が出ない、または絞り込むと 0 件になる場合は、ラベルを作る前にクロールしていないかを確かめます（「Label Updater」の実行で直ります）。
「検索オプション」に「ラベル」の一覧が出ない場合は、ラベルの「パーミッション」に検索する人のロールが含まれているかを確かめます。

検索結果のリンクとパスマッピング
================================

共有フォルダーやアーカイブの検索結果をクリックすると、Fess がファイルを読み出してブラウザーに返します。
これは［全般］の「検索ファイルプロキシ」による動作で、初期状態で有効です。
ブラウザーから ``smb://`` や ``file:`` の URL を直接開けなくても、ファイルを開けます。

アーカイブと同じファイルを社内の Web サーバー（ここでは ``https://archive.example.com/``）でも公開していて、そちらを開かせたい場合は、パスマッピングで URL を変換します。

［クローラー］>［パスマッピング］>［新規作成］で、次の項目を入力して［作成］をクリックします。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 項目
     - 値
   * - 正規表現
     - ``^file:/data/archive/(.*)$``
   * - 置換
     - ``https://archive.example.com/$1``
   * - 処理の種別
     - 表示

「処理の種別」は最初「クロール」が選ばれているので、必ず「表示」に変えます。

- 表示: インデックスの URL は ``file:/data/archive/...`` のまま、検索結果のリンクをクリックしたときの移動先だけを変えます。作成した時点から効き、再クロールは不要です
- クロール: インデックスに保存する URL そのものを書き換えます。再クロールするまで効かず、ラベルの「対象とするパス」も書き換えた後の ``https://`` の URL に合わせる必要があります

設定後に検索し、アーカイブの結果をクリックすると ``https://archive.example.com/`` の Web サーバーが開くことを確かめます。
