==========================
データストアクロールの基本
==========================

はじめに
========

Google Drive や Slack、データベースの中身は、ウェブクロールやファイルクロールでは検索対象にできません。
CSV ファイルもファイルクロールでは 1 ファイルが 1 件の文書になり、行ごとには検索できません。
Fess ではこれらを「データストア」として、プラグイン（データストアコネクタ）経由でレコード単位に取り込みます。

データストアの設定画面は、ウェブやファイルシステムの設定画面とは項目が異なります。
どの値を URL やタイトルにするかを自分で書く必要があり、初期値のままだとログインなしで検索できる状態で登録されます。
処理に失敗しても、ジョブが「OK」と表示されることがあります。

この記事では、どのコネクタにも共通する仕組みを Fess 15.9 に沿って説明します。
CSV ファイルを使った小さな例で、プラグインの導入から、設定、実行、結果の確認までを一通り行います。
コネクタごとの認証やパラメーターは、末尾に挙げる各記事とリファレンスを参照してください。

ウェブ・ファイルクロールとの違い
================================

ウェブクロールとファイルクロールでは、Fess がリンクやフォルダーをたどり、取得した文書からタイトルや本文を自動で取り出します。
データストアクロールでは、コネクタが API やファイルからレコードを読み出します。
そのレコードのどの値をインデックスのどのフィールドに入れるかは、設定の「スクリプト」に書きます。

Fess 本体にはデータストアのハンドラーは含まれていません。
［クローラー］>［データストア］の「ハンドラー名」のプルダウンに表示されるのは、インストール済みの ``fess-ds-*`` プラグインが提供するハンドラーだけです。

このほか、データストアの設定には次の違いがあります（後の節で説明します）。

- 設定画面に「ラベル」の項目がない
- ［クローラー］>［ドキュメントブースト］のルールが適用されない

プラグインをインストールする
============================

ここでは例として CSV コネクタ ``fess-ds-csv`` を使います。
プラグインのバージョンは、使用している Fess のマイナーバージョンに合わせます（15.9 なら 15.9.x）。

管理画面から入れる場合は、［システム］>［プラグイン］で［インストール］をクリックします。
［リモート］タブのプルダウンで ``fess-ds-csv`` を選んで［インストール］をクリックします。
手元の jar ファイルを使う場合は［ローカル］タブを使います。

ZIP パッケージや RPM / DEB でインストールした環境では、コマンドラインからも入れられます。

.. code-block:: bash

    bin/fess-setup install plugin fess-ds-csv:15.9.0

Docker では、``compose.yaml`` の ``fess01`` の ``environment`` に ``FESS_PLUGINS`` を追加し、起動時に入れます。
複数のプラグインは空白で区切って並べます（カンマ区切りではありません）。

.. code-block:: yaml

    environment:
      - "FESS_PLUGINS=fess-ds-csv:15.9.0"

.. code-block:: bash

    docker compose -f compose.yaml -f compose-opensearch3.yaml up -d

Docker で管理画面からインストールしたプラグインはコンテナ内に置かれるため、コンテナを作り直すと消えます。
Docker では ``FESS_PLUGINS`` を使うほうが確実です。
環境変数を変えて ``up -d`` するとコンテナが作り直されます。
そのとき失われる設定については :doc:`guide-02` を参照してください。

管理画面や ``fess-setup`` でインストールした場合は、Fess を再起動します（``FESS_PLUGINS`` は Fess の起動前に入れるため、再起動は不要です）。
再起動後、［クローラー］>［データストア］>［新規作成］の「ハンドラー名」に ``CsvDataStore`` が表示されれば導入できています。

設定画面の 3 つの欄
===================

データストア設定の中心は「ハンドラー名」「パラメーター」「スクリプト」の 3 つの欄です。

.. list-table::
   :header-rows: 1
   :widths: 20 80

   * - 欄
     - 内容
   * - ハンドラー名
     - 使うコネクタ。例: ``CsvDataStore``、``SlackDataStore``
   * - パラメーター
     - コネクタへの指示。1 行に 1 つ ``キー=値`` で書く（読み込むファイル、接続先、認証情報など）
   * - スクリプト
     - インデックスのフィールドへの対応付け。1 行に 1 つ ``フィールド名=式`` で書く

パラメーターの ``script_type``
------------------------------

新規作成画面の「パラメーター」欄には、最初から ``script_type=javascript`` が入っています。
これは「スクリプト」欄の式を JavaScript で評価するという指定です。
コネクタのパラメーターは、この行を残したまま下に書き足します。

``script_type`` の行を消すと、スクリプトは Groovy として評価されます（15.9 より前に作った設定を動かし続けるための既定値です）。
Groovy で評価するには ``fess-script-groovy`` プラグインが必要です。
標準の Docker イメージには含まれますが、slim イメージには含まれません。
プラグインがない環境では、式を含む行の評価が ``groovy is not found`` というエラーで失敗し、そのレコードは登録されません（``title=subject`` のように右辺が項目名だけの行は、スクリプトエンジンを通さずにそのまま値が使われます）。
逆に標準の Docker イメージでは、行を消しても Groovy で評価されて動いてしまうため、気付きにくくなります。
コネクタのリファレンスにある例を「パラメーター」欄に貼り付けるときは、``script_type=javascript`` の行を消さないようにしてください。

スクリプトの書き方
------------------

「スクリプト」欄の各行は、左辺がインデックスのフィールド名、右辺が JavaScript の式です。
文字列はダブルクォーテーションで囲みます。
行末にセミコロンを付けないでください。
セミコロンを付けると式の値が ``null`` になり、そのフィールドは何も設定されません。
エラーやログは出ないため、フィールドが空になっていることでしか気付けません（詳しくは末尾のリファレンスの「JavaScript によるスクリプト」を参照）。

右辺で参照できる項目名はコネクタによって異なります。

- CSV・JSON・データベースのコネクタは、列名やフィールド名をそのまま参照します（CSV は ``cell1``、``cell2`` … でも参照できます）
- 多くのクラウド系コネクタは、取得したオブジェクトを接頭辞付きで渡します。たとえば Box・Google Drive・OneDrive は ``file.*``、Slack は ``message.*``、Jira は ``issue.*``、Salesforce は ``object.*`` です

使える項目名は、各コネクタのリファレンス（``https://fess.codelibs.org/ja/stable/config/datastore/ds-<名前>.html``）のスクリプトの説明で確認してください。
``file.url`` とすべきところを ``url`` と書くなど、定義されていない名前を参照すると式の評価が失敗し、そのレコードは登録されません。

例：CSV ファイルを検索できるようにする
======================================

社内 FAQ を CSV で管理していて、それを検索できるようにする例です。
次の内容を UTF-8 で ``faq.csv`` として保存します。

.. code-block:: text

    faq_id,question,answer
    1,経費精算の締め日はいつですか,経費は毎月末までに申請してください。
    2,社外から社内システムに接続するには,VPN クライアントを使って接続してください。
    3,入館証をなくしたときは,総務部に連絡して再発行を依頼してください。

Excel で保存した CSV は、多くの場合 UTF-8 ではなく MS932 です。
その場合は、後で示すパラメーターに ``file_encoding=MS932`` を指定します。
ファイルは、Fess のクローラーが読めるパスに置きます。
クローラーは Fess と同じサーバー上で動くため、ZIP や RPM / DEB の環境では、Fess を実行しているユーザーが読めるディレクトリに置きます。
Docker で試すだけなら、コンテナ内にコピーする方法が手軽です（コンテナを作り直すと消えます）。

.. code-block:: bash

    docker cp faq.csv fess01:/tmp/faq.csv

［クローラー］>［データストア］で［新規作成］をクリックし、次のように入力します。

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - 項目
     - 値
   * - 名前
     - 社内FAQ
   * - ハンドラー名
     - ``CsvDataStore``
   * - パラメーター
     - 下記
   * - スクリプト
     - 下記
   * - パーミッション
     - ``{role}guest`` のまま（ログインなしで検索できてよい FAQ のため）

パラメーター:

.. code-block:: properties

    script_type=javascript
    files=/tmp/faq.csv
    file_encoding=UTF-8
    has_header_line=true

スクリプト:

.. code-block:: javascript

    url="https://intranet.example.com/faq/" + faq_id
    title=question
    content=question + " " + answer
    digest=answer
    label="faq"

``has_header_line=true`` を指定すると、1 行目の列名（``faq_id``、``question``、``answer``）をスクリプトで参照できます。
``url`` には、検索結果のリンクをクリックしたときに開く、そのレコードを表示できるページの URL を指定します。
この例の URL は架空のものです。
実際の FAQ ページの URL に置き換えてください。

［作成］で保存したら、後で説明する「スケジュール」の手順でジョブを作って実行し、「結果を確かめる」の手順で確認します。
うまくいけば、ログアウトした状態（またはブラウザーのプライベートウィンドウ）の検索画面で「VPN」と検索すると、2 件目の FAQ が見つかります。
``{role}guest`` の文書は、ログインしていない利用者と、ロール ``guest`` を持つユーザー（初期ユーザー ``admin`` を含む）に表示されます。ほかのユーザーでログインしている場合は表示されません。

ラベル ``faq`` を検索画面の絞り込みに表示したい場合は、［クローラー］>［ラベル］で「値」が ``faq`` のラベルを作成します（次の「ラベル」の節を参照）。

インデックスのフィールド
========================

スクリプトでよく設定するフィールドは次のとおりです。

.. list-table::
   :header-rows: 1
   :widths: 20 80

   * - フィールド
     - 説明
   * - ``url``
     - 必須。検索結果のリンク先。レコードごとに一意な値にする
   * - ``title``
     - 検索結果の見出し。検索対象
   * - ``content``
     - 本文。検索対象
   * - ``digest``
     - 検索結果に表示する要約
   * - ``label``
     - ラベルの値（後述）
   * - ``role``
     - 閲覧できるロール。コネクタが ACL を提供する場合に使う（後述）

このほか、``config_id``、``boost``、``role``、``virtual_host``、``mimetype`` などは自動で設定されます（``boost``、``role``、``virtual_host`` は設定画面の「ブースト値」「パーミッション」「仮想ホスト」の値です）。
スクリプトで同じフィールドを指定した場合は、スクリプトの値で上書きされます。

``url`` は次の点に注意してください。

- 式の値が ``null`` になったレコードは登録されません。CSV コネクタはそのような行を障害URL に記録せず、``fess-crawler.log`` に件数を WARN で 1 行出すだけです
- 文書 ID は URL、ロール、仮想ホストから作られます。``url`` が空文字列のレコードや同じ ``url`` のレコードは、ロールと仮想ホストも同じなら同じ文書 ID になり、上書きし合って最後の 1 件しか残りません

パーミッション
==============

新規作成画面の「パーミッション」には、最初から ``{role}guest`` が入っています。
この値は、そのデータストアから登録されるすべての文書のロールになります。
ゲストロールはログインしていない利用者に付与されるため、このままでは文書はログインなしで検索できます。
社内 FAQ のように公開してよいデータなら、このままで構いません。

閲覧者を限定したいデータでは、次のどちらかで制御します。

- 「パーミッション」欄を、見せたいグループやロール（例: ``{group}sales``）に書き換える。データストア内の全文書に同じ権限が付きます
- コネクタが元のサービスの共有設定（ACL）からロールを作る場合は、スクリプトで ``role=file.roles`` のように対応付ける。項目名はコネクタによって異なり（Slack は ``message.roles``）、ACL の取得に追加のパラメーターが必要なコネクタもあります（Slack の ``permission_sync=true`` など）。各コネクタのリファレンスを確認してください

ACL を使う場合は、「パーミッション」欄の ``{role}guest`` を消してください。
Box、Slack、Microsoft 365（OneDrive）などのコネクタは、「パーミッション」欄の値も ``file.roles`` / ``message.roles`` に加えて返します。
そのため、``{role}guest`` を残すと、ACL を設定してもログインなしで検索できる状態のままになります。

逆に、「パーミッション」欄を空にして、スクリプトでも ``role`` を設定しないと、文書にロールが 1 つも付きません。
この文書は検索画面ではだれにも表示されません。

ロールは文書を登録するときに書き込まれます。
パーミッションやスクリプトを変更した場合は、再クロールするまで既存の文書には反映されません。
ロールやグループの設計は :doc:`guide-05` で説明しています。

ラベル
======

データストアの設定画面には、ウェブやファイルシステムの設定画面にある「ラベル」の項目がありません。
ラベルを付けるには、次のどちらかを使います。

- スクリプトに ``label="faq"`` のように書く。そのデータストアの全文書に付きます
- ［クローラー］>［ラベル］で、「対象とするパス」に文書の URL に一致する正規表現を書く。登録時に URL がこの正規表現と照合され、一致した文書にラベルが付きます

「対象とするパス」は URL 全体との一致で判定されるため、前方一致にしたい場合は末尾に ``.*`` を付けます（例: ``https://intranet\.example\.com/faq/.*``）。

注意: スクリプトで付けたラベルは、その文書の URL に一致するラベルが［クローラー］>［ラベル］に 1 つでもあると失われ、一致したラベルだけが残ります。
ウェブクロール用に作ったラベル（例: ``https://intranet\.example\.com/.*``）や、「除外するパス」だけを設定したラベルも一致の対象です。
スクリプトでラベルを付ける場合は、文書の URL に一致するラベルがないことを確認してください。

ラベルの「値」は英数字とアンダースコアだけで指定します（ハイフンや日本語は使えません）。
検索画面のラベルの選択肢に表示したい場合は、スクリプトで付ける場合も、同じ値のラベルを［クローラー］>［ラベル］に登録してください。
その場合、「対象とするパス」は空でも構いません。

ブースト値
==========

データストアの設定画面の「ブースト値」（初期値 ``1.0``）は、そのデータストアから登録されるすべての文書に設定されます。
ブースト値は検索時のスコアに掛け合わされます。
特定のデータソースの文書を上位に出したい場合は、このブースト値を変えます。

［クローラー］>［ドキュメントブースト］のルールは、ウェブクロールとファイルクロールで登録する文書にだけ適用されます。
データストアの文書には適用されません。

スケジュール
============

初期状態のジョブ「Default Crawler」は毎日 0:00 に実行され、有効なウェブ・ファイルシステム・データストアの設定をすべてクロールします。
データストアごとに実行の頻度を変えたい場合は、設定ごとにジョブを作ります。

1. ［クローラー］>［データストア］の一覧で設定名をクリックし、詳細画面を開きます
2. ［新しいジョブの作成］をクリックします。スケジューラの作成画面が開き、「名前」（``Data Crawler - 社内FAQ``）と、この設定だけをクロールするスクリプトが入力済みになっています
3. 「スケジュール」に cron 形式（分 時 日 月 曜日）で実行時刻を入力し、［作成］をクリックします。例: ``0 2 * * *``\ （毎日 2:00）

「スケジュール」が空のジョブは定期実行されず、手動でしか実行されません。
すぐに試すには、［システム］>［スケジューラ］で作成したジョブを開き、［今すぐ開始］をクリックします。

設定ごとのジョブを作っても、「Default Crawler」は引き続きその設定もクロールします。
二重に実行したくない場合は、そのデータストア設定の「状態」を無効にします。
「Default Crawler」は有効な設定だけを対象にしますが、設定 ID を指定したジョブは無効な設定もクロールします。
すべての設定に専用のジョブを作る場合は、「Default Crawler」の「スケジュール」を空にする方法もあります（\ :doc:`guide-04`\ ）。

文書の有効期限
==============

データストアで登録した文書には有効期限が付きます。
期限は、そのクロールを開始した時刻から［システム］>［全般］の「以前のドキュメントを削除」の日数（初期値 ``3`` 日）後です。
期限を過ぎた文書は、毎分実行されるジョブ「Doc Purger」がインデックスから削除します。
同じ文書が次のクロールで登録し直されると、期限は延びます。

このため、次の 2 つの場合は、文書が検索結果から消えてしまいます。

- ジョブの実行間隔が「以前のドキュメントを削除」の日数より長い場合
- 変更された項目だけを読む差分クロール（Git や Google Drive の ``incremental=true`` など）で、変更のない文書が登録し直されない場合

設定ごとに期限を変えるには、パラメーターに ``time_to_live`` を分単位で指定します（例: ``time_to_live=11520`` で 8 日）。
元のデータから削除されたものも、この期限が切れると検索結果から消えます。
期限を長くしすぎると、削除がいつまでも反映されません。

結果を確かめる
==============

データストアのクロールでは、ジョブの状態が「OK」でも成功したとは限りません。
コネクタで例外が発生しても、Fess はそれを設定単位やレコード単位で記録して処理を続けます。
このため、ジョブログの状態は「OK」になり、［システム情報］>［クロール情報］の「クローラーの状態」も変わりません。
次の順に確認してください。

1. ［システム情報］>［ジョブログ］で、ジョブが終了していることを確認します。「結果」の ``Data Config Id:`` の行に、対象の設定 ID が出ています
2. ［システム情報］>［クロール情報］で、そのセッションの「インデックスのサイズ (データストア)」を確認します。そのセッションで登録した文書の件数です（「Default Crawler」では全データストアの合計）
3. ［システム情報］>［障害URL］で、エラーが記録されていないか確認します
4. ［システム情報］>［ログファイル］から ``fess-crawler.log`` をダウンロードし、ERROR と WARN の行を確認します（Docker と RPM / DEB では ``/var/log/fess/``、ZIP パッケージでは ``logs/`` にあります）
5. ［システム情報］>［検索］で ``label:faq`` のように検索し、件数を確認します

失敗のしかたによって、手がかりが残る場所が異なります。

.. list-table::
   :header-rows: 1
   :widths: 30 35 35

   * - 状況
     - 障害URL
     - fess-crawler.log
   * - ハンドラーが見つからない（設定後にプラグインを削除した場合など）
     - 記録なし
     - ``DataStore(...) is not found.``
   * - 設定全体の失敗（コネクタが処理を続けられない認証エラーや、必須パラメーターの不足など）
     - 1 件。URL 欄は ``D<設定ID>:<設定名>``
     - ``Failed to process a data crawling: <設定名>``
   * - レコード単位の失敗（スクリプトの評価エラーなど）
     - レコードごと。CSV では ``<ファイルのパス>:<行番号>``
     - WARN の行

CSV コネクタでは、``files`` に指定したファイルが見つからない場合や、拡張子が ``.csv`` / ``.tsv`` でない場合も、エラーにはなりません。
``is not found.`` と ``No CSV file.`` の WARN を出して、0 件で終了します。

［システム情報］>［検索］はパーミッションによる絞り込みをせずにすべての文書を表示するため、件数の確認に向いています。
一方で、権限が意図どおりかどうかの確認には使えません。
権限は、対象の利用者でログインした状態（``{role}guest`` の文書ならログアウトした状態）で、通常の検索画面から確認してください（:doc:`guide-05`）。

コネクタが渡している項目名が分からない場合は、クローラーのログレベルを DEBUG にすると、取得した値がログに出るコネクタがあります（CSV コネクタは各行の値を出力します）。
設定方法は\ `データストアコネクタの概要 <https://fess.codelibs.org/ja/stable/config/datastore/ds-overview.html>`__\ の「デバッグ設定」を参照してください。
