======================================
ロールとグループで検索結果を出し分ける
======================================

はじめに
========

社内の文書を 1 つの Fess で検索できるようにすると、次に問題になるのが「誰に何を見せるか」です。
人事部の評価資料が全社員の検索結果に出てしまっては困りますし、逆に全社向けの規程が一部の人にしか見えないのも困ります。

Fess では、クロール設定の「パーミッション」に書いた値が文書ごとに記録され、検索のたびに、ログインしている利用者の権限と照合されます。
本記事では、部署ごとの出し分けを Fess 15.9 で設定し、利用者ごとに見える文書を確かめるところまでを順に進めます。

この記事の手順を実行すると、次のことができるようになります。

- 部署・役員・全社員の 3 種類の公開範囲を、グループとパーミッションで設定する
- Active Directory のグループをそのままパーミッションに使う
- ラベルの表示を、文書と同じ範囲に揃える
- 利用者ごとに見える文書と、文書に記録された権限を確かめる

SSO の設定は :doc:`guide-15`、仮想ホストによる複数組織の使い分けは :doc:`guide-13` で扱います。

権限の仕組み
============

パーミッションの書き方
----------------------

クロール設定の「パーミッション」には、次の形式の値を 1 行に 1 つずつ書きます。
いずれか 1 つでも利用者の権限と一致すれば、その文書は検索結果に表示されます。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 書き方
     - 一致する利用者
   * - ``{user}ユーザー名``
     - そのユーザー本人
   * - ``{group}グループ名``
     - そのグループに所属するユーザー
   * - ``{role}ロール名``
     - そのロールを持つユーザー
   * - ``(deny){group}グループ名``
     - 一致したユーザーには、ほかの値で許可されていても表示しない（``{user}`` と ``{role}`` にも付けられます）

利用者が持つ権限
----------------

検索のたびに、Fess は利用者の権限を次のように決めます。

- ログインしている利用者: ``{user}本人``、所属グループの ``{group}``、持っているロールの ``{role}``
- ログインしていない訪問者: ``{role}guest``

ここで重要なのは、ログインした利用者には ``{role}guest`` が付かないことです。
新しいクロール設定の「パーミッション」には ``{role}guest`` が初めから入っています。
そのままにすると、ログインしていない訪問者には見えて、ログインした利用者には見えない文書になります。
全社員に見せたい文書には、全社員が所属するグループ（またはロール）をパーミッションに書きます。

なお、初期ユーザーの ``admin`` はロール ``admin`` と ``guest`` を持っています。
管理画面にログインしたままのブラウザーで検索すると ``admin`` として検索されるため、``{role}guest`` の文書だけが表示され、部署の文書は表示されません。

ロールとグループの使い分け
--------------------------

照合の仕組みは、ロールもグループも同じです。
違いは値の出どころです。
Fess のユーザー管理では、ユーザーごとにロールとグループの両方を割り当てられます。
LDAP（Active Directory）連携では、所属グループ（``memberOf``）が ``{group}グループ名`` になります（DN に ``ou=Role`` を含むエントリだけは ``{role}`` になります）。

本記事では、Fess のユーザーでも Active Directory でも同じパーミッションの値が使えるように、部署や全社員などの組織の単位はすべてグループで表します。

この記事で作る構成
==================

社内ポータル ``https://intra.example.com/`` に、部署ごとのページと全社向けのページがある会社を例にします。

.. list-table:: グループとユーザー
   :header-rows: 1
   :widths: 20 40 40

   * - ユーザー
     - 所属
     - グループ
   * - ``sato``
     - 営業部
     - ``Sales``、``AllStaff``
   * - ``suzuki``
     - 開発部
     - ``Engineering``、``AllStaff``
   * - ``tanaka``
     - 人事部
     - ``HR``、``AllStaff``
   * - ``yamada``
     - 役員
     - ``Executives``、``AllStaff``

.. list-table:: クロール設定のパーミッション
   :header-rows: 1
   :widths: 25 40 35

   * - クロール設定
     - URL
     - パーミッション
   * - 営業部
     - ``https://intra.example.com/sales/``
     - ``{group}Sales`` と ``{group}Executives``
   * - 開発部
     - ``https://intra.example.com/dev/``
     - ``{group}Engineering`` と ``{group}Executives``
   * - 人事部
     - ``https://intra.example.com/hr/``
     - ``{group}HR`` と ``{group}Executives``
   * - 全社共通
     - ``https://intra.example.com/common/``
     - ``{group}AllStaff``

この設定で、利用者ごとに見える文書は次のようになります。

.. list-table:: 利用者ごとに見える文書
   :header-rows: 1
   :widths: 30 70

   * - 利用者
     - 検索結果に出る文書
   * - ``sato``
     - 営業部、全社共通
   * - ``suzuki``
     - 開発部、全社共通
   * - ``tanaka``
     - 人事部、全社共通
   * - ``yamada``
     - 営業部、開発部、人事部、全社共通
   * - ログインしていない訪問者
     - なし
   * - ``admin``\ （検索画面）
     - なし

ログインしていない訪問者にも全社共通の文書を見せたい場合は、全社共通の設定に ``{role}guest`` も加えます。
この場合、``admin`` にも全社共通の文書が表示されます。

グループ名は大文字・小文字を区別して照合されます。
``{group}sales`` と ``{group}Sales`` は別のグループとして扱われるため、グループの名前とパーミッションの値は同じ綴りで書きます。

Fess のユーザーで設定する
=========================

グループとユーザーを作る
------------------------

1. 管理画面の［ユーザー］>［グループ］で［新規作成］をクリックし、「名前」に ``Sales`` を入力して［作成］をクリックします。``Engineering``、``HR``、``Executives``、``AllStaff`` も同じように作成します
2. ［ユーザー］>［ユーザー］で［新規作成］をクリックし、「ユーザー名」・「パスワード」・「パスワード(確認)」を入力します。パスワードは 8 文字以上にします
3. 「グループ」で、上の表のとおりに所属グループを選び、［作成］をクリックします

ユーザー、グループ、ロールは OpenSearch に保存されるため、Docker でコンテナを作り直しても残ります。

クロール設定を作る
------------------

部署ごとに、［クローラー］>［ウェブ］でクロール設定を作ります。
次の表は営業部の例です。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 項目
     - 値
   * - 名前
     - ``営業部ポータル``
   * - URL
     - ``https://intra.example.com/sales/``
   * - クロール対象とするURL
     - ``https://intra.example.com/sales/.*``
   * - パーミッション
     - 初期値の ``{role}guest`` を消して、次の 2 行を入力します

::

    {group}Sales
    {group}Executives

開発部・人事部・全社共通も、URL とパーミッションを表のとおりに変えて作成します。
作成したら、［システム］>［スケジューラ］の「Default Crawler」で［今すぐ開始］をクリックし、クロールを実行します。
クロールの完了の確かめ方は :doc:`guide-02` を参照してください。

.. note::

   ファイルシステムのクロール設定（SMB やローカルファイル）では、ファイルの ACL から読み取った権限が、「パーミッション」の値に\ **加えて**\ 文書に記録されます。
   この動作は既定で有効です。
   そのため、ファイルサーバーの文書は、「パーミッション」に書いた範囲よりも広く表示されることがあります。
   ACL との組み合わせ方は :doc:`file-server-search` を参照してください。
   データストアのクロール設定のパーミッションは :doc:`datastore-basics` で扱います。

Active Directory のグループを使う
=================================

利用者を Active Directory で管理している場合は、Fess にユーザーやグループを作る代わりに、LDAP 連携を設定します。
ログインした利用者の ``memberOf`` 属性に入っているグループが、``{group}`` の権限になります。

LDAP の接続を設定する
---------------------

［システム］>［全般］の「LDAP」の欄に入力し、［更新］をクリックします。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 項目
     - 入力例
   * - LDAP URL
     - ``ldap://ad.example.com:389``
   * - Base DN
     - ``dc=example,dc=com``
   * - Bind DN
     - ``cn=fess,cn=Users,dc=example,dc=com``\ （検索用のサービスアカウント）
   * - パスワード
     - サービスアカウントのパスワード
   * - User DN
     - ``%s@example.com``\ （``%s`` にログイン名が入ります）
   * - アカウントフィルター
     - ``sAMAccountName=%s``
   * - memberOf属性
     - ``memberOf``

各項目の詳細と、入れ子のグループを解決するための「グループフィルター」の書き方は、`LDAP統合ガイド <https://fess.codelibs.org/ja/stable/config/ldap-integration.html>`__ を参照してください。

.. warning::

   ［全般］の設定は ``system.properties`` に保存されます。
   docker-fess の構成では、このファイルは ``fess01`` コンテナの中にあるため、``down`` → ``up`` でコンテナを作り直すと消えます（:doc:`guide-02` の「停止と再開」）。

グループ名とパーミッションの対応
--------------------------------

グループの DN のうち、いちばん末端の ``CN`` の値がグループ名になります。

.. list-table::
   :header-rows: 1
   :widths: 55 45

   * - memberOf の値
     - 利用者の権限
   * - ``CN=Sales,OU=Groups,DC=example,DC=com``
     - ``{group}Sales``
   * - ``CN=AllStaff,OU=Groups,DC=example,DC=com``
     - ``{group}AllStaff``

Active Directory 側のグループ名を ``Sales``・``Engineering``・``HR``・``Executives``・``AllStaff`` にしておけば、前の章のクロール設定がそのまま使えます。
名前が違う場合は、パーミッションの値を Active Directory のグループ名に合わせて書き換えます。

全社員用のグループは、全員が直接所属するグループを用意してください。
Active Directory のプライマリグループ（通常は ``Domain Users``）は ``memberOf`` 属性に含まれないため、``{group}Domain Users`` と書いても一致しません。

利用者にどの権限が付いたかは、``org.codelibs.fess.ldap`` のログを DEBUG にすると確かめられます。
LDAP から権限を取得したときに、``Roles:`` で始まる行が ``fess.log`` に出力されます。
設定方法は LDAP統合ガイドの「デバッグ設定」を参照してください。
この行の値は、後述する内部形式（``2Sales`` など）で表示されます。

SSO（Entra ID、OpenID Connect、SAML、SPNEGO）でログインさせる場合は、方式ごとに ``fess-sso-*`` プラグインが必要です。
グループやロールの受け取り方も方式ごとに異なるため、:doc:`guide-15` を参照してください。

ラベルの表示範囲を揃える
========================

ラベルにも「パーミッション」があり、検索画面のラベルの選択肢にそのラベルを表示するかどうかを決めます。
文書を見せるかどうかには影響しませんが、新しいラベルにも ``{role}guest`` が初めから入っているため、そのままではログインした利用者の選択肢に表示されません。

人事部の文書に付けるラベルの例です。
［クローラー］>［ラベル］で［新規作成］をクリックし、次のように入力します。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 項目
     - 値
   * - 名前
     - ``人事部``
   * - 値
     - ``hr``\ （英数字とアンダースコアのみ）
   * - 対象とするパス
     - ``https://intra.example.com/hr/.*``
   * - パーミッション
     - ``{group}HR`` と ``{group}Executives``\ （文書と同じ範囲）

ラベルのパーミッションは保存した時点で選択肢に反映されます。
一方、ラベルを文書に付ける「対象とするパス」はクロール時に適用されるため、ラベルを作った後にクロールを実行します。

権限を変えたら再クロールする
============================

パーミッションはクロール時に文書へ記録されます。
クロール設定の「パーミッション」を変更しても、すでにインデックスにある文書の権限は変わりません。
変更後に、そのクロール設定を含むジョブ（「Default Crawler」など）を実行してください。

ウェブとファイルシステムのクロール設定では、権限が変わった文書は次のクロールで取得し直され、同じ URL の古い文書は置き換えられます。
再クロールが終わるまでは、古い権限のまま検索結果に出続けます。
公開範囲を狭めたときは、すぐにクロールを実行してください。

特定のクロール設定だけをすぐに再クロールしたい場合は、そのクロール設定の詳細画面で［新しいジョブの作成］をクリックし、作成したジョブを［今すぐ開始］で実行します。

動作を確かめる
==============

利用者ごとに検索する
--------------------

1. ブラウザーのプライベートウィンドウで ``http://localhost:8080/`` を開きます。管理画面にログインしているウィンドウでは ``admin`` として検索されるためです
2. ログインせずに検索し、部署と全社共通の文書が表示されないことを確かめます
3. 検索画面の上部のログインリンクから ``sato`` でログインし、営業部と全社共通の文書だけが表示されることを確かめます
4. 画面上部のユーザー名をクリックして「ログアウト」を選び、``suzuki``、``tanaka``、``yamada`` でも同じように確かめます

確かめるときは、どの文書にも含まれる語（例: 社名）で検索すると、表示される文書の範囲を比べやすくなります。

文書に記録された権限を見る
--------------------------

思ったとおりに表示されない場合は、文書に記録された権限を確認します。

1. 管理画面の［システム情報］>［検索］を開き、文書の URL やタイトルの語で検索します。この画面は権限による絞り込みをせず、すべての文書を表示します
2. 対象の文書の［更新］をクリックすると編集画面が開き、``role`` 欄に記録された権限が表示されます。確認するだけで、保存はしないでください

``role`` 欄の値は、次の内部形式で表示されます。

.. list-table::
   :header-rows: 1
   :widths: 35 30 35

   * - パーミッション
     - role 欄の表示
     - 例
   * - ``{user}ユーザー名``
     - ``1`` + 名前
     - ``1sato``
   * - ``{group}グループ名``
     - ``2`` + 名前
     - ``2Sales``
   * - ``{role}ロール名``
     - ``R`` + 名前
     - ``Rguest``
   * - ``(deny)`` 付き
     - 先頭に ``D``
     - ``D2Sales``

営業部の文書の ``role`` 欄が ``2Sales`` と ``2Executives`` なら、パーミッションは設定どおりに記録されています。
``Rguest`` が残っている場合は、パーミッションの変更後に再クロールしていないか、初期値の ``{role}guest`` を消し忘れています。

ログインしない利用者に何も見せない
==================================

社外の人がアクセスできるネットワークに Fess を置く場合や、そもそも未ログインでの検索を許さない場合は、［システム］>［全般］の「ログインが必要」を有効にします。
有効にすると、ログインしていない訪問者は検索できなくなります。

パーミッションによる出し分けとは独立した設定です。
``{role}guest`` が付いた文書が残っていても、ログインしていない訪問者に表示されることはなくなります。
この設定も ``system.properties`` に保存されるため、Docker では LDAP の設定と同じ注意が必要です。
