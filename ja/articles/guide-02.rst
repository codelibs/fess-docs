=====================================
Docker で Fess を動かして検索してみる
=====================================

はじめに
========

Fess を検討し始めたとき、最初に知りたいのは「自分の手元で動かすと、どんな検索ができるのか」です。
本記事では、Docker を使って Fess 15.9 を起動し、Web ページを 20 ページほどクロールして、検索構文を試すところまでを順に進めます。

題材には、Fess 公式サイトにある日本語の「検索ガイド」（AND 検索やワイルドカード検索などを説明したページ群）を使います。
対象を一か所に絞るので、クロールは数分で終わり、検索結果の中身も読んで確かめられます。

この記事の手順をそのまま実行すると、次のことができるようになります。

- Fess と OpenSearch を Docker Compose で起動し、停止・再開する
- 管理者の初回ログインと、求められるパスワード変更を済ませる
- Web クロール設定を作り、クロールを実行し、完了を確かめる
- AND・OR・除外・フレーズ・フィールド指定の検索を試す

本番環境向けの設定（監視、バックアップ、SSO、規模の拡張）は扱いません。
末尾の「次に読む記事」から、目的に合う記事に進んでください。

この記事で作る環境
==================

docker-fess リポジトリの Compose ファイルを使うと、次の 2 つのコンテナが起動します。

.. list-table::
   :header-rows: 1
   :widths: 20 40 40

   * - サービス
     - 役割
     - データの置き場所
   * - ``fess01``
     - Fess 本体（イメージ ``ghcr.io/codelibs/fess:15.9.0``）。ポート 8080 で検索画面と管理画面を提供します
     - ボリュームなし（コンテナ内）
   * - ``search01``
     - OpenSearch（イメージ ``ghcr.io/codelibs/fess-opensearch``）。ポート 9200 も公開されます
     - ボリューム ``search01_data`` と ``search01_dictionary``

インデックス、クロール設定、ユーザー、ジョブログなどはすべて OpenSearch に保存されるため、``search01_data`` ボリュームに残ります。
一方、管理画面の［システム］>［全般］で変更した設定は ``fess01`` コンテナ内の ``system.properties`` に保存されます。
この違いは、後の「停止と再開」で効いてきます。

.. warning::

   この構成の OpenSearch はセキュリティプラグインが無効のまま、ホストのポート 9200 で公開されます。
   手元の PC で試すための構成として使い、共有サーバーで動かす場合は :doc:`guide-10` と :doc:`guide-15` を先に確認してください。

準備
====

- Docker と Docker Compose（``docker compose`` コマンド）が使えること
- Docker が使えるメモリが 4GB 以上あること（OpenSearch のヒープだけで 1GB を確保します）
- インターネットに接続できること（イメージの取得とクロールに使います）

Linux または WSL2 では、OpenSearch の起動に必要な ``vm.max_map_count`` を引き上げます。

::

    $ sudo sysctl -w vm.max_map_count=262144

この値は OS を再起動すると元に戻ります。
続けて使う場合は ``/etc/sysctl.conf`` にも書いておきます。

::

    $ echo 'vm.max_map_count=262144' | sudo tee -a /etc/sysctl.conf

Fess を起動する
===============

15.9.0 用の Compose ファイルを取得する
--------------------------------------

docker-fess の既定ブランチの Compose ファイルは、新しい版のリリースに合わせて更新されます。
版を 15.9.0 に固定するため、``v15.9.0`` タグのファイルを取得します。

::

    $ mkdir fess-docker
    $ cd fess-docker
    $ curl -LO https://raw.githubusercontent.com/codelibs/docker-fess/v15.9.0/compose/compose.yaml
    $ curl -LO https://raw.githubusercontent.com/codelibs/docker-fess/v15.9.0/compose/compose-opensearch3.yaml

``compose.yaml`` には ``fess01`` だけが定義されており、``fess01`` が依存する ``search01`` は ``compose-opensearch3.yaml`` にあります。
そのため、以降の ``docker compose`` コマンドには、毎回 2 つのファイルを ``-f`` で指定します。
片方だけで実行すると、起動も停止も正しく行われません。

起動して、準備ができるまで待つ
------------------------------

::

    $ docker compose -f compose.yaml -f compose-opensearch3.yaml up -d

初回はイメージの取得があるため、数分かかります。
状態は次のコマンドで確認します。

::

    $ docker compose -f compose.yaml -f compose-opensearch3.yaml ps

``search01`` が healthy になってから ``fess01`` が起動します。
``fess01`` の STATUS が ``(healthy)`` になれば準備完了です。
``fess01`` のヘルスチェックは ``/api/v2/health`` を呼んでおり、起動直後の 120 秒は猶予期間として扱われます。

なかなか healthy にならないときは、ログを確認します。

::

    $ docker compose -f compose.yaml -f compose-opensearch3.yaml logs -f fess01

ポート 8080 が他のアプリケーションで使われている場合は、``compose.yaml`` の ``ports`` を ``"9080:8080"`` のように変更します。
その他の起動トラブルは `インストールのトラブルシューティング <https://fess.codelibs.org/ja/stable/install/troubleshooting.html>`__ を参照してください。

ブラウザーで ``http://localhost:8080/`` を開くと、Fess の検索画面が表示されます。
まだ何もクロールしていないので、この時点では検索しても結果は出ません。

管理画面にログインする
======================

``http://localhost:8080/admin/`` を開き、ユーザー名 ``admin``、パスワード ``admin`` でログインします。

初期パスワードの ``admin`` は使い続けられない設定になっているため、ログインすると「パスワードを更新する必要があります」という画面に進みます。

1. 「新しいパスワード」と「新しいパスワードの確認」に、同じパスワードを入力します（8 文字以上）
2. ［更新］をクリックします

更新が終わると、管理画面のダッシュボードが開きます。
以降は新しいパスワードでログインします。
このパスワードは OpenSearch に保存されるので、コンテナを作り直しても残ります（ボリュームごと削除した場合は ``admin`` に戻ります）。

クロール設定を作る
==================

対象を決める
------------

今回は Fess 公式サイトの日本語「検索ガイド」をクロールします。
``https://fess.codelibs.org/ja/stable/user/`` の下にある 20 ページ程度で、``stable`` は現在の安定版（15.9）のドキュメントを指します。

ウェブクロール設定を登録する
----------------------------

1. 管理画面の左メニューから［クローラー］>［ウェブ］を開きます
2. ［新規作成］をクリックします
3. 次の項目を入力します。ほかの項目は初期値のままにします

   .. list-table::
      :header-rows: 1
      :widths: 30 70

      * - 項目
        - 値
      * - 名前
        - ``Fess 検索ガイド``
      * - URL
        - ``https://fess.codelibs.org/ja/stable/user/index.html``
      * - クロール対象とするURL
        - ``https://fess.codelibs.org/ja/stable/user/.*``
      * - 最大アクセス数
        - ``50``

4. ［作成］をクリックします

各項目の意味は次のとおりです。

- 「名前」は必須です。空のままでは作成できません
- 「URL」はクロールの始点です
- 「クロール対象とするURL」は正規表現で、これに一致しない URL へのリンクはたどりません。空にすると、ページ内のリンクを他のバージョンや他の言語、外部サイトまでたどってしまいます
- 「最大アクセス数」は、正規表現の書き間違いに備えた上限です

初期値のままにした項目のうち、「スレッド数」は ``1``、「間隔」は ``10000`` ミリ秒です。
1 ページごとに 10 秒待つので、相手のサイトへの負荷を抑えられます。
「パーミッション」には ``{role}guest`` が入っているので、ログインしていない利用者も検索結果を見られます。
部署ごとに見せ分ける方法は :doc:`guide-05` で扱います。

.. note::

   ``/ja/15.9/`` のような版番号つきの URL を対象にすると、1 ページも登録されません。
   これらのページには ``/ja/stable/`` を指す ``<link rel="canonical">`` が入っています。
   Fess のクローラーはそのページを登録せず、代わりに canonical の URL をたどります。
   その URL が「クロール対象とするURL」の正規表現から外れるため、何も登録されません。
   自社サイトを対象にする場合も、canonical の URL が正規表現に含まれるかを確かめてください。

.. tip::

   ［システム］>［ウィザード］でも、「名前」・「クロールパス」・「最大アクセス数」・「深さ」を入力するだけでクロール設定を作り、そのまま［クロールの開始］まで進めます。
   ただし、ウィザードで作った設定には「クロール対象とするURL」が入らないため、リンクをたどる範囲を絞れません。
   今回のように対象を絞りたい場合は、上記の［クローラー］>［ウェブ］から作成してください。

クロールを実行して完了を確かめる
================================

クロールを開始する
------------------

設定を保存しただけでは、クロールは始まりません。

1. ［システム］>［スケジューラ］を開きます
2. 一覧の「Default Crawler」をクリックします
3. ［今すぐ開始］をクリックします

「Default Crawler」は、有効なウェブ・ファイルシステム・データストアのクロール設定をまとめて実行するジョブです。
このジョブには初期状態で cron 式 ``0 0 * * *`` が設定されており、毎日 1 回、自動でも実行されます。
コンテナを動かしたままにすると、翌日以降も同じ設定で再クロールされます。

今回の設定では 20 ページ程度を 10 秒間隔で取得するため、終わるまでの目安は数分です。

終わったことを確かめる
----------------------

次の順に確認します。

1. ［システム情報］>［ジョブログ］を開きます。「Default Crawler」の行の「状態」が「実行中」から「OK」に変われば、ジョブは終わっています。「失敗」の場合は、その行をクリックして詳細を開き、「結果」を確認します
2. ［システム情報］>［クロール情報］を開き、一覧のいちばん上（最新）のセッションをクリックします。「インデックスのサイズ (ウェブ/ファイル)」が、今回のクロールで登録された文書の数です。今回は 20 前後になります
3. 件数が想定より少ない場合は、［システム情報］>［障害URL］を開きます。接続エラーなどで取得できなかった URL と、その理由が記録されています

ジョブが「OK」でも、登録件数が 0 のことがあります。
「クロール対象とするURL」の正規表現に一致しなかった URL は、エラーではなく対象外として扱われるため、障害URL にも記録されません。
件数が 0 で障害URL も空なら、URL と正規表現の書き方（``https`` と ``http`` の違い、末尾の ``.*`` の有無など）を見直してください。

検索してみる
============

``http://localhost:8080/`` を開いて検索します。
検索画面は Fess に同梱のテーマ ``bootstrap`` です。

まずは ``ワイルドカード`` と入力して検索してみてください。
ワイルドカード検索のページや、特殊文字のページが結果に並びます。
結果のタイトルをクリックすると、元のページ（fess.codelibs.org）が開きます。

続いて、次の検索語を順に入力してみます。
いずれも、いまクロールしたページで結果を確かめられます。

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - 入力する検索語
     - 意味
   * - ``フィールド URL``
     - スペースで区切ると AND 検索になり、両方を含むページだけが出ます
   * - ``ワイルドカード OR 曖昧``
     - どちらかを含むページが出ます。``OR`` は半角大文字で、前後にスペースが必要です
   * - ``検索 -ラベル``
     - 「ラベル」を含むページを結果から除きます。``-`` は除外したい語の直前に付けます
   * - ``"範囲指定検索"``
     - 引用符で囲んだ語句を、その並びのまま含むページを探します（フレーズ検索）
   * - ``title:ソート``
     - タイトルに「ソート」を含むページだけを探します（フィールド指定検索）

``or`` や ``and`` のように小文字で書くと演算子にならず、ふつうの検索語として扱われます。

ここで使った構文と、ワイルドカード・曖昧検索・範囲指定などの残りの構文は、いまクロールした `検索ガイド <https://fess.codelibs.org/ja/stable/user/index.html>`__ に説明があります。
気になった構文を自分の Fess で検索し、そのページを開いて読む、という使い方もできます。

停止と再開
==========

停止のしかたによって、残るものが変わります。

.. list-table::
   :header-rows: 1
   :widths: 30 35 35

   * - 操作
     - 残るもの
     - 失われるもの
   * - ``stop`` → ``start``
     - すべて
     - なし
   * - ``down`` → ``up -d``
     - OpenSearch に保存されたもの（インデックス、クロール設定、ユーザーとパスワード、ジョブログなど）
     - ``fess01`` コンテナ内に保存されたもの（［システム］>［全般］で変更した設定など）
   * - ``down -v``
     - なし
     - すべて（管理者パスワードも ``admin`` に戻ります）

ふだん止めるときは ``stop``、再開は ``start`` を使います。

::

    $ docker compose -f compose.yaml -f compose-opensearch3.yaml stop
    $ docker compose -f compose.yaml -f compose-opensearch3.yaml start

``down`` はコンテナを削除します。
OpenSearch のデータはボリュームに残りますが、［全般］の設定は ``fess01`` コンテナ内の ``system.properties`` に書かれているため、コンテナと一緒に消えます。

::

    $ docker compose -f compose.yaml -f compose-opensearch3.yaml down

試用を終えて、データも含めて片付ける場合は ``-v`` を付けます。
ボリュームも削除され、元に戻せません。

::

    $ docker compose -f compose.yaml -f compose-opensearch3.yaml down -v

［全般］で変えた設定の一部は、``compose.yaml`` の ``FESS_JAVA_OPTS`` で指定しておくと、コンテナを作り直しても残ります（SSO の接続設定のように、この方法では指定できない項目もあります）。
手順は `Docker でのインストール (詳細) <https://fess.codelibs.org/ja/stable/install/install-docker.html>`__ を参照してください。
